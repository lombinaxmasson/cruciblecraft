## 5. R2 · Form-gate T8 哈希与 pin-chain

### 为什么

`src/main/resources/data/cruciblecraft/material_registration_gate.json` 中
`sources.t8_source_backed_pipe_forms.sha256` 没有跟上当前
`tools/t8_pipe_readiness.json`。

这是根节点 stale。修复 gate 后，其原始字节 SHA 会变化；任何记录 gate SHA 的
下游 artifact 都可能随之 stale。因此这不是“改一个 JSON 就结束”。

### 第一步：只让 builder 写 gate

```powershell
$env:PYTHONUTF8=1
python tools/build_gt6_material_form_gate.py --write
python tools/build_gt6_material_form_gate.py --check --reference-only
```

允许生成：

- `src/main/resources/data/cruciblecraft/material_registration_gate.json`；
- `tools/gt6_l1b_selected_recipe_operands.json`。

### 第二步：立即定向验证

```powershell
python tools/run_python_tests.py --suite affected --path src/main/resources/data/cruciblecraft/material_registration_gate.json
```

必须消失的错误：

```text
material gate source hash drifted: t8_source_backed_pipe_forms
```

### 第三步：审查 diff

预期语义变化仅为：

- T8 readiness 的 SHA-256/currentness；
- 已在 08-17 迁入的 rock/cutter 形态可达性；
- 与这些输入直接关联的计数或摘要。

若 source fact 数、材料全集、GT revision、mortar 分类或大量配方语义改变，停止。

### 第四步：前向传播

先写 material gate，再写消费它的下游；不能依赖当前 policy 中
`build_component_rules` 位于 material form gate 之前的显示顺序。

至少检查以下波次：

```text
material gate
  → component rules
  → T4–T8 readiness / machine crafting
  → T10–T12 closure
  → T13–T20 currentness
  → T21/T22.5 compact consumers
```

执行原则：

1. 对每个候选 builder 先运行其 `--check`；
2. 只有确认为 stale 才运行该 builder 的写模式；
3. 每个波次完成后跑 `affected`；
4. 每个波次审查 diff，再进入下一波；
5. 不使用整库 `rebuild_artifacts.py --verify` 盲刷。

可以使用 `rebuild_artifacts.py --only ... --verify` 处理一个明确、无危险 builder
的小波次，但不得把下列项混进自动写入：

- `compare_gt6_recipes`；
- `build_t14_recipe_load_benchmark`；
- report-owned 的 `build_t21_readiness`；
- 默认会重建整份历史投影的 T12a。

### T12a 特例

`tools/t12a_machine_readiness.json` 只允许更新已经声明的 `source_hashes`：

- `material_registration_gate`；
- `machine_crafting_readiness`。

不得运行默认写模式重建整份历史投影。若这两个 hash 再次 stale：

1. 先确认其余 T12a 字段与已关闭证据字节一致；
2. 使用受约束的 source-hash-only 路径更新；
3. 若仓库没有受约束路径，停止并补一个只更新 hash、且断言其他字段不变的模式；
4. 不用临时脚本或手工编辑 JSON。

### Windows `OSError 22`

若大 JSON 的：

```python
Path.write_text(..., newline="\n")
```

在 Windows 报 `OSError: [Errno 22] Invalid argument`：

- 将该 builder 的写入改为 `write_bytes(stable(...).encode("utf-8"))`；
- 或写入同目录 `.tmp` 后 `replace()`；
- 补定向测试，证明 `--check` 字节稳定；
- 不缩短内容、不手改输出、不关闭 currentness 检查。

### 完成判据

- form-gate 定向测试通过；
- 下游没有因 gate 新 SHA 留下的真实 stale；
- T12a 历史投影没有被整份重写；
- `compare_gt6_recipes` baseline、mortar expectation 和 fixed source revision 未动。

## 14. 禁止命令与安全提交

git status --short
