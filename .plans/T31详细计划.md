## 0. 先读这一节

### 0.1 什么时候才允许开卡

不得根据 T30 文档中的预写状态开始。先执行：

```powershell
$env:PYTHONUTF8=1
python tools/run_full_verification.py --check-ready
```

必须同时看到：

```text
full_verification_report.status = READY
t30_readiness_acceptance.status = T30_READY
```

并确认：

- 60 Hopper + 60 Queue Hopper + `steel_dust_funnel` 已完整闭合；
- T30 publication/load 已实测；
- 无 placeholder 或半成品 registry id；
- `mod_version = 0.1.0-beta.1`；
- `rc_number` 仍为 null；
- T24-F003 / F005 仍待本卡复测，没有被 T30 假关闭。

任一项不满足：回到 [T30详细计划.md](T30详细计划.md)，不要创建 T31 artifact，
不要改版本。

### 0.2 一句话判据

> 消费真实 T30_READY；在声明的 ≥16 GB 环境实现并执行 T24 target/stress 规模
> 测量，关闭 F003/F005；重放 source/closure 与全部 Java/GameTest，证明 Datagen
> 幂等、存档、网络、客户端/专服、可选依赖和安装包可靠；只有 release blocker
> 为零后才把版本改为 `0.1.0-rc.1`，从同一冻结树构建可验证发行物并绑定
> `T31_READY`。

### 0.3 本卡必须交付

1. T24-F003 target/stress 路由规模复测；
2. T24-F005 target/stress wall-clock、retained memory、network sync 复测；
3. 声明环境、原始样本与可复算摘要；
4. Datagen 双跑、Python closure/source-replay、JUnit、GameTest；
5. beta.1 → rc.1 存档升级与二次载入；
6. client/server 网络与材料 handshake；
7. 无可选依赖和 EMI/Jade/KubeJS 支持矩阵；
8. fresh install、dedicated server 与发行 jar 冒烟；
9. RC release notes、README、玩家指南与 metadata 一致；
10. jar/zip 内容检查和 SHA-256 manifest；
11. `T31_READY` 与 RC soak 交接。

### 0.4 本卡明确不做

- 不新增机器、方块、物品、材料、RecipeMap 或 recipe family；
- 不补桶、抽屉、Fluid Funnel、Canner、Boxinator；
- 不借规模复测重写物流架构，除非真实 blocker 有可复现证据；
- 不把 T24/T26 历史伪写成“当时已经测过”；
- 不把 F003/F005 gap 填 0；
- 不以跨机器 wall-clock 差异制造 blocker；
- 不升级 Minecraft、NeoForge、Java 或可选依赖版本；
- 不用 RC 卡做一般 UI/美术 polish；
- 不自动 commit、tag、push 或上传；
- 不发布 GA / `1.0.0`。

### 0.5 失败时的正确状态

```text
T31 = OPEN / BLOCKED
mod_version = 0.1.0-beta.1
rc_number = null
release artifact = forbidden
```

可以修复 release blocker 并重测，但不能先生成 RC 包再把 blocker 降为 known issue。

### 0.6 九条硬规则

1. T30_READY 前零写入。
2. F003/F005 不能继续 SKIP；缺少 ≥16 GB 环境就是 blocker。
3. 先完成可复算 harness，再跑昂贵测量。
4. 先通过 pre-version gate，后改 `mod_version`。
5. 修复后立刻跑定向测试，不把多个 blocker 累到最终 record。
6. JUnit、GameTest、Datagen、规模测量、打包、record 全部串行。
7. snapshot 冻结后零编辑。
8. 包必须来自被验证的同一棵树，不使用旧 `build/libs`。
9. RC1 不是 GA；soak 中只接 release blocker。

## 6. R2 · target/stress harness 与 instrumentation

### 6.1 harness 必须消费 manifest

从 `tools/t24_workload_manifest.json` 读取：

- scenario identity；
- counts/composition；
- seed；
- loaded chunks；
- warmup/sampling ticks。

不要在 Java/Python 各维护第二份 500/2,000 常量表。

### 6.2 target

必须构建：

- 250 fluid pipes；
- 250 item pipes；
- 24 covers；
- 24 processing machines；
- 8 energy converters；
- 3 multiblocks；
- 1 petroleum chain；
- warmup 600；
- sampling 12,000。

### 6.3 stress

必须构建：

- 1,000 fluid pipes；
- 1,000 item pipes；
- 96 covers；
- 96 processing machines；
- 32 energy converters；
- 12 multiblocks；
- 4 petroleum chains；
- warmup 600；
- sampling 12,000。

### 6.4 必测字段

- route discovery visited max / p95；
- route cache entries；
- transfer conservation；
- tick wall-clock p50/p95/max；
- reload/index wall-clock；
- retained heap before/after受控 GC；
- allocation（若现有协议支持）；
- actual encoded network sync bytes；
- loaded chunks/entities/block entities；
- OS/CPU/RAM/Java/JVM args/Xmx/GC；
- sample count、seed、warmup；
- failure/timeout。

原始样本和摘要分开保存。单次 `System.nanoTime` 差值不是完整证据。

### 6.5 instrumentation 纪律

- 默认关闭，不改变普通 runtime；
- 只观测，不改调度/缓存；
- traversal counter 每次边界清零；
- network bytes 用实际 codec encode；
- retained memory 使用固定 GC/稳定等待协议；
- 无法测的轴 pending，不填 0。

### 6.6 先用 small fixture 自证

立即验证：

- manifest identity/counts 全等；
- counter 不负、不溢出；
- transfer 守恒；
- 同 seed 结构摘要稳定；
- failure 使任务非零退出；
- artifact 能被 builder `--check`；
- instrumentation enabled/disabled 不改变结果语义。

只有这些 Java/Python 定向测试全绿，才允许占用 16 GB 环境。

## 7. R3–R4 · 声明环境与 F003/F005 复测

### 7.1 环境门

记录：

```text
physical RAM >= 16 GiB
OS name/version/arch
CPU model/logical processors
Java vendor/version/VM
JVM args and Xmx
GC
free disk
source tree identity
mod_version（此时仍 beta.1）
```

≥16 GB 是物理环境，不是给 JVM `-Xmx16G`。Xmx 必须给 OS/file cache 留余量，并记录
实际值。

环境不足时：

```text
T31 = BLOCKED_ENVIRONMENT
F003/F005 = OPEN
version = beta.1
```

### 7.2 target 先跑

1. clean build harness；
2. 构建 target；
3. 核对实际 count；
4. warmup 600；
5. sampling 12,000；
6. 运行 5 个独立 sample；
7. 保存原始日志与 machine-readable summary；
8. builder `--check`。

立即检查：

- visited 未越 32,768；
- conservation 全绿；
- 无 OOM/watchdog；
- network bytes 不是估算；
- wall-clock/memory 字段完整。

target 失败时不继续 stress。

### 7.3 stress 后跑

释放 target JVM/daemon 后，用同一协议跑 stress。不能：

- 与 target 并发；
- 用 target 平均值外推；
- 删除慢样本；
- 降低 manifest counts；
- 把 OOM/timeout 写成 0。

stress 用于发现非线性。超 soft 但低于 hard 时按 T14 标
`SOFT_BUDGET_EXCEEDED`，不自动等于 blocker；越 hard 必须阻断。

### 7.4 replacement 完成判据

F003：

- target/stress route visited 有真实数值；
- cap 32,768 未越；
- topology 与 manifest 全等；
- conservation 全绿。

F005：

- target/stress 均不再 SKIP；
- wall-clock、retained memory、network sync 有方法、值、单位和环境；
- hard gate 有 verdict；
- 没有 zero-filled metric。

只能完成 target 时，T31 保持 `BLOCKED_PENDING_STRESS_MEASUREMENT`。本文不允许口头
放行；若以后要改，必须另行显式修改产品合同。

### 7.5 发现 blocker 时

只做有界修复：

1. 写复现测试；
2. 定位到 traversal/cache/sync/save 的具体边界；
3. 做最小修复；
4. 立即跑定向测试；
5. 重跑 target；
6. target 绿后重跑 stress；
7. 重建 T31 scale artifact。

不得提高 hard ceiling、删断言或缩 topology。

## 15. 验证矩阵：何时立即跑，何时合并跑

| 修改/动作 | 必须立即验证 | 可整合验证 | 最终证据 |
|---|---|---|---|
| T31 schema/readiness | stale test + affected | Python closure | record |
| target/stress harness | small fixture + counter JUnit | target | scale artifact |
| instrumentation | counter/codec test | target/stress | scale artifact |
| 性能修复 | 对应定向测试 | 重跑 target/stress | load report |
| F003/F005 disposition | builder `--check` | readiness | record |
| Datagen | 连续两次 | full verification | tree digest |
| Java 修复 | 精确 `--tests` | 全量 JUnit | record |
| GameTest 修复 | 对应用例 | 全量 GameTest | record |
| save migration | beta copy 立即重测 | compatibility matrix | report |
| network codec/version | codec/handshake test | client/server smoke | report |
| optional dependency | 各矩阵项分别跑 | compatibility 汇总 | report |
| version/metadata | `generateModMetadata` + test | package | embedded version |
| jar/zip | 内容/启动/hash | release manifest | readiness |
| snapshot 文档 | currentness + diff check | 冻结 | record |

原则：

- harness、counter、codec、save、版本传播改后立刻验证；
- 全量套件与可选依赖各自完成后汇总；
- package smoke 必须对发行 jar；
- final record 不替代定向验证。
