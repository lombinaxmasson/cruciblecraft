## 0. 范围与不变式

- 发行 jar 才使用 bundle；`src/recipe_generated/resources` 与开发运行保持
  原来的单家族 JSON。
- bundle 内每个成员保留原 `source_id`、`family_id`、`stable_id` 和完整
  definition。`CompactRecipeFamilySource` 在 loader 中继续使用原 source id。
- 不改变 `CompactPublicationPolicy` 的 family_count、relation_count 或
  membership_root_sha256，不抬高 512 KiB 单条 wire 上限、64 MiB 同步门或
  任何 load ceiling。
- 带有条件、transport fragment 或无法在预算内装箱的文件保持原样。

## 1. 实施

1. Python 只做只读 probe，按 host/target map 测量 bundle 装箱数量、JSON
   压缩收益和每箱 wire 预算；不改 `tools/recipe_bulk` 和波次台账。
2. 新增 `compact_gt_recipe_family_bundle` recipe type。bundle entry 携带
   原始 `source_id` 与 `CompactGTRecipeFamilyDefinition`；RecipeManager
   只负责解析 bundle，`GTRecipeMapLoader` 在分片重组、去重和发布策略
   校验之前拆出原 source。
3. `release-resources.gradle` 从 `build/resources/main` 读取 compact family
   JSON，在 jar 专用输出目录生成 bundle，排除已经打包的原成员；普通
   JSON 压缩和哈希剥离继续生效。
4. bundle 装箱同时受关系数、dictionary entries、JSON 保守字节预算约束；
   单箱 wire 编码必须小于 `CompactRecipeWireLimits.MAX_RECIPE_ENTRY_WIRE_BYTES`。

## 2. 验收

- 开发树原文件可单独加载；发行 bundle 加载后的 provider snapshot 与开发
  树完全一致：family/relation counts、stableFingerprint、去重结果和发布
  策略 membership root 全部相同。
- `RecipeManager` 能解析 bundle，GTRecipeMapLoader 不再把 bundle 资源 id
  当成 semantic family id。
- 每个发行 bundle wire 编码不超过 512 KiB；jar 中 compact family 文件数
  显著下降，jar 总大小和条目数有实测记录。
- 相关单测、recipe load/sync 测试与发行 jar server smoke 通过；关闭为
  `runtime_ready`。

## 3. 禁止

- 不在 Python 生成器中改输出格式或重写台账。
- 不合并或重命名 family_id/stable_id，不修改 publication policy JSON。
- 不把 bundle 解析放进 EMI 显示层或用 bundle 资源 id 替代原 source id。
- 不删除无法证明等价的条件、分片或 provenance 数据。
