> `shaped_catalyst` 工具配方从发行数据包文件改为配方重载时生成。
> 不新增工具、材料、配方语义或 GT6 获得方式。

## 0. 范围与不变式

- `WorkbenchToolRecipePlan.plan()` 仍是唯一规划来源。
- 运行时生成的 recipe id、`ShapedCatalystRecipe` JSON、材料组件、
  催化剂损耗、镜像规则和结果物必须与原有 datagen 文件语义相同。
- 数据包中的同名 recipe 继续优先；运行时生成只使用 `putIfAbsent`。
- `tools/assemble/**` 与 `tools/pattern/**` 保留为静态资源。
- 不把工具配方改成 `material_rule`，不使用 stand-in 材料，不改变
  RecipeManager 的全局 load/sync 上限。

## 1. 实施

1. 把 `ModRecipeProvider` 的 planned recipe 物化逻辑抽到运行时可调用的
   `WorkbenchToolRuntimeRecipes`，datagen 使用同一实现。
2. 在 RecipeManager 解析 JSON 前，将计划配方编码为
   `cruciblecraft:shaped_catalyst` JSON 并加入输入 map。
3. 用当前 25,590 个文件做语义 parity；通过后停止生成逐材料
   `recipe/tools/**` 文件，重新生成资源并清除旧文件。
4. 更新只依赖静态文件存在的 datagen/resource 测试，使其验证运行时计划
   或保留的静态 assembly/pattern 文件。

## 2. 验收

- `WorkbenchToolRecipePlan` 的所有 planned paths 都能在 RecipeManager 中
  找到对应的 `ShapedCatalystRecipe`。
- iron knife、zirconium MV wrench battery 等代表性 recipe id 存在，
  且 crafting matches、result components、catalyst remainder 与旧 JSON
  相同。
- 数据包同名 recipe 覆盖运行时默认值。
- 单元测试、相关 GameTest、RecipeCensus 通过。
- 发行 jar 中 `recipe/tools/**` 只保留 18 个 assembly 与 13 个 pattern
  文件；关闭成熟度为 `runtime_ready`。

## 3. 禁止

- 删除或重写 `WorkbenchToolRecipePlan` 的 GT6 条件与材料形式门。
- 以通用 matcher 替换现有 recipe id、配方书条目或 EMI 语义。
- 把创造栏、GameTest 注入或 ItemEntity 世界生成当作获得方式。
- 为使测试通过而修改 recipe budget、sync limit 或 load budget。
