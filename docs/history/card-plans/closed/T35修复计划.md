## 1. 修复结论

T35 的分母、运行时集合、配方 family 聚合和预算 opening 可以保留：

- T13 七表共 765 identities；
- exclusion 为 763 source sites / 1,701 expanded registrations / 194 families；
- runtime expected 与 mapped 均为 20,553；
- 78,682 个 `ordinary_optional` rows 唯一归入 5,718 families；
- aggregate validator 全为 0；
- T14 13 轴与 `publication_delta = 0/0/0` 成立；
- `T32-VD-001` 已关闭。

需要修复的不是这些计数，而是它们到 1.x portfolio 的投影：

1. `machine_tiers.json` 的 33 variants / 11 kinds 没有独立、可审计的 1.x scope 判定；
   RU/KU/HU 材料档、EU voltage 与 TU/TIME 被混写成同一张 selected matrix；
2. 当前 generated topology 只有 T38–T46 storage cards，不能证明机器与 EU 轨已经关闭、
   无需开卡，或将在何处开卡；
3. 原 T35 计划固定 `T36 → T37 → T38+`，当前 T38–T46 却只依赖 T36；
4. Storage 28/624 已进入 P1，但 Chests、Safes、Fluid Containers、Tank、Pump、Sorting
   只被统一标为无 `portfolio_scope` 的 P2 deferred；
5. T35 工作日志已写“完成”，而 roadmap 与 active plan 状态尚未同步；
6. ordinary census integration 在 census → topology → readiness 层重复 full replay；
   约 31 分钟与一次未复现的并发 stale 记入 verification debt。

因此，T35R 采用以下判据：

> 保留已验证的 census 数值，重开 portfolio scope 与 topology closure；只有机器/EU/TU、
> storage、固定卡序和后续 P2 epoch 都有明确机器契约后，才重新签发
> `T35_CENSUS_READY` 并将 T36 设为唯一 active 卡。

## 3. 固定设计决策

### 3.1 priority、disposition 与 scope 三分

新增独立字段 `portfolio_scope`：

```text
in_scope_1x
candidate_1x
post_1x
out_of_scope
```

三套字段不得互相替代：

- `portfolio_priority`：P0 / P1 / P2 / P3；
- `disposition`：implemented / planned / deferred / out_of_scope；
- `portfolio_scope`：当前 1.x 是否承诺关闭。

每条 identity 另有 `scope_contract`：

- `in_scope_1x`：`closure != closed` 必须有 fixed-card owner 或 generated-card owner；
- `candidate_1x`：必须有 `admission_criterion`、`measurement_owner` 和 `recheck_epoch`；
- `post_1x`：必须有具体 `subsequent_track`，禁止只写 `post_1_0` 或光秃的 `post_1x`；
- `out_of_scope`：必须有产品排除理由；
- `deferred` 不能自动证明对象不在 1.x。

### 3.2 默认 scope 映射

在 family 级 override（storage / machine track）之后，剩余 identity 按下列确定性规则赋值；
无法赋值则 fail closed，`unscoped` 计入 validator。

| 条件 | `portfolio_scope` | `scope_contract` |
|---|---|---|
| `disposition == out_of_scope` | `out_of_scope` | `exclusion_reason = reason` |
| T37 pilot family | `in_scope_1x` | owner = 固定卡 T37 |
| Storage 28/624 与 `mass_storage_logistics` | `in_scope_1x` | owner = generated storage card |
| `exclusion/hopper` | `in_scope_1x` | 已由 T30 关闭 |
| Chest / Safe | `post_1x` | `subsequent_track = post_1x/storage-adjacent` |
| Tank | `post_1x` | `subsequent_track = post_1x/multiblock-tanks` |
| Pump / Sorting | `post_1x` | `subsequent_track = post_1x/logistics-adjacent` |
| Fluid Containers | `candidate_1x` | measurement owner T37，epoch `T37_closure` |
| `runtime_local:machine_tier/*`（33 行） | `in_scope_1x` | catalog migration owner = T36 |
| `implemented` 且 `closure == closed` | `in_scope_1x` | 无未关闭工作项 |
| `planned` 且 P0/P1 | `in_scope_1x` | 进入 fixed 或 generated work set |
| 配方 `registered_playable` 且 P2 blocked | `candidate_1x` | measurement owner T37，epoch `T37_closure` |
| bath / smelter / mixer 大分母 | `post_1x` | `subsequent_track = post_1x/large_recipe_maps` |
| missing-host recipe | `out_of_scope` | 无当前可玩 host |
| 其余 `deferred` P3 / 历史 `post_1_0` | `post_1x` | `subsequent_track = post_1x/<table-or-domain>` |

### 3.3 topology 分两个 epoch

当前“一次 T35 为所有未来 P2 编号”的承诺与“T37 后才有 P2 实测”互相矛盾，改为：

1. **Epoch A · T35R**
   - 固定 T36、T37；
   - 为无条件 `in_scope_1x` 的未关闭 P0/P1 生成卡；
   - T38 起连续编号；
   - 所有 generated cards 必须经过 T37 全局执行门。
2. **Epoch B · T37 closure**
   - 只消费 T37 实测后的 P2 admission；
   - 追加新卡，不重编号 Epoch A；
   - 未通过 soft-budget admission 的 family 保持 `candidate_1x` deferred。

`t35_card_topology.json` 必须记录：

```json
{
  "topology_epoch": "T35R_A",
  "numbering_policy": "regenerate_once_then_append_only",
  "global_execution_gate": "T37",
  "epoch_b": {
    "policy": "append_only",
    "may_renumber_epoch_a": false,
    "admits": "ADMITTED_UNDER_SOFT candidate_1x families after T37 closure"
  }
}
```

T35R 完成前，现有 T38–T46 视为 provisional。由于全部 `started=false`，允许一次确定性重排；
T35R readiness 签发后，Epoch A 编号冻结。

### 3.4 固定卡序

机器可读顺序固定为：

```text
T35R
  └─ T36 machine registry/tier matrix
       └─ T37 ordinary_optional pilot
            └─ Epoch A generated T38+
                 └─ Epoch B append-only cards
```

每张 Epoch A generated card：

- `depends_on` 必须包含 T37；
- 若存在更具体 generated dependency，也必须同时保留；
- 不再只依赖 T36；
- validator 必须拒绝绕过 T37 的 generated card。

## 4. 机器与 EU / TU 范围修复

### 4.1 三套分母，禁止混写

`machine_tiers.json` 的 33 行**不是** RU/KU/HU/TU 四轨笛卡尔表。实测为：

| 轨 | 能量 identity | 在 33 行中的位置 | 1.x 结论 |
|---|---|---|---|
| RU | `KINETIC_ROTATION` | 15 行 / 5 kinds | A：已覆盖所选材料档 |
| KU | `KINETIC_PUSH` | 6 行 / 2 kinds | A：已覆盖所选材料档 |
| HU | `HEAT` | 9 行 / 3 kinds | A：已覆盖所选材料档 |
| EU | `ELECTRIC` | 3 行 electrolyzer，`electric_tier_*` 是 voltage band 而非材料档 | A：1.x 只关闭这三行 voltage pilot |
| TU | `TIME` | **0 行**；不在本 catalog | A_empty_in_catalog：TIME identity 与已关闭的 TU host kinds 不走 33 行材料档 |

禁止：

- 将 33 行的存在等价为 T36 refactor 已关闭；
- 将 11 kinds 自动笛卡尔扩展成所有 material；
- 将 `electric_tier_*` 继续解释成 material tier；
- 将 T13 的 73 个 incomplete machine kinds 整体自动纳入 1.x；
- 把 Autoclave / Bath / Coagulator / Generifier 当成 33 行缺失的 TU 材料变体。

### 4.2 新工件

新增：

```text
tools/t35_machine_track.json
tools/build_t35_machine_track.py
tools/tests/test_build_t35_machine_track.py
```

builder 必须逐行输出 33 variants 的 stable id、kind、source id/tier/row、material、
energy identity、material tier 或 EU voltage band、registration 状态、T36 migration
owner，以及 `portfolio_scope` / disposition / closure。

机器轨最终结论（本卡写死，不再留到 T36）：

```text
A. selected RU/KU/HU 材料档与 EU 三行 voltage pilot 已由现有 33 variants 完整覆盖；
   generated_material_cards_required = false
   generated_eu_cards_required = false
   generated_tu_cards_required = false
   T36 只做无损 catalog 重构，并把 electric_tier_* 迁移为 voltage 语义。
```

Roadmap 收窄：

- “EU voltage 轨全部关闭”改为：1.x 只关闭电解槽三行 voltage-band pilot；其余 EU
  voltage denominator 为 `post_1x/eu-voltage`；
- “分别关闭 RU、KU、HU、TU”改为：RU/KU/HU 指 33 行所选材料档；TU 指已关闭的
  `TIME` energy identity 与已实现的 TU host kinds，不是本 catalog 的材料矩阵。

### 4.3 EU voltage 轨

EU 必须与 material tier 分离：

- 电解槽三行是 1.x voltage semantics pilot；
- T36 负责 catalog 与保存/执行语义迁移；
- 不生成额外 Epoch A EU 内容卡。

### 4.4 TU / TIME

- energy identity `TIME`（short name TU）保持 `in_scope_1x + implemented`；
- Autoclave / Bath 等已关闭 kind 保持 kind-level `in_scope_1x`；
- 它们不是 33 行材料档的缺失行，不进入 Epoch A generated cards。

## 8. 验证性能与并发稳定性

证明强度不降低，但消除重复 full replay：

### 8.1 分层

- ordinary `census` integration：
  - foundation builders 使用 compact/reference currentness；
  - downstream builder 只消费并校验已提交 artifact hash；
  - 不在 census、topology、readiness 每层重复 recipe/machine full replay。
- `census-replay` repair gate：
  - 对 recipe families 和 machine source projection 各执行一次 full replay；
  - 产出本次 replay receipt；
  - T35R 最终闭卡必须运行。

### 8.2 并发

新增测试：

- 两个只读 `--check` 并发运行，输出与退出码一致；
- check 不写 artifact、临时文件或 generated tree；
- T35 `write_stable` 使用同目录原子替换；
- stale 诊断必须打印首个不同字段或 hash，不只打印整文件 stale。

### 8.3 时间目标

- cached ordinary census integration：目标不超过 5 分钟；
- full replay 可更慢，但同一 profile 中每个 expensive projection 只运行一次；
- verification 输出记录各 builder/test suite wall time；
- 时间目标不是 readiness PASS 条件。超过目标记 verification debt，不阻断
  `T35_CENSUS_READY`。先前约 31 分钟与未复现的并发 stale 同此处理。
