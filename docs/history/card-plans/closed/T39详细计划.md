普通 material rod/ingot 不表达 reactor rod 的 active、depleted、product state 或行为
生命周期，因此这些 source objects 不建立 CrucibleCraft runtime alias。它们不生成 T39
生产配方、不生成 support，也不算 T39 completed。

## 5. 分层玩家路径

```text
B0 = frozen T21 closure without T39 production/support
B1 = B0 + 34 locked support routes
B2 = B1 + 32 locked production relations
```

Admission：

- support recipe 输入在其发现前的 closure 可达，禁止循环自证；
- support target 必须属于 production lock 的反向依赖切片；
- 每条 production relation 的输入在 B1 可达；
- 每条输出已注册并在 B2 可达；
- phase-deferred family 不参加 1.x player-path gate。

## 6. Runtime、publication 与 load

一张 T39 Card 拥有两个 `(target_map, publication_group)` policy/load 单位：

```text
cruciblecraft:t39_centrifuge_singleton = 19 families / 19 relations
cruciblecraft:t39_centrifuge_multi     = 3 families / 13 relations
```

每组独立生成 query-addressable shards、独立实测 policy/cache，最后原子 publish。
Card logical total 32 不是单 query candidate。T14 64/128 控制 routed candidate interval；
overflow 只能在 hard ceiling 内，不能通过提高 ceiling 掩盖失败。

测试边界：

- production JUnit/GameTest 只验证 lock 的精确 22/32；
- catalog JUnit 只验证 157/250 fixture 的 decode/router capacity；
- fixture load 不能成为 production winner；
- registry-touching 测试必须先调用共享幂等 Minecraft bootstrap。

## 7. Closing accounting

```text
opening ordinary families = 5639
closed_by_t39 = 22
reclassified_to_nuclear = 7
remaining ordinary families = 5610
```

`closed_by_t39` 与 `reclassified_to_nuclear` 必须分列。后者是 denominator maintenance，
不是配方完成量，也不计入 T39 的实现绩效。

Publication、load、census、topology、readiness 与 GameTest receipt 必须绑定同一
production lock hash、22/32 分母、34-support root 和 runtime dependency aggregate root。

## 8. 执行顺序

```text
R0 production lock + operand disposition
R1 production/catalog/support resource isolation
R2 B0/B1/B2 layered player path
R3 production + fixture JUnit and isolated GameTest
R4 materialization measurements + policy + publication/load
R5 census + topology + readiness
R6 clean generation, no-fixture-in-JAR and documentation verification
```

任何阶段失败都必须修复权威输入或撤回生产成员，禁止用 placeholder、lossy alias、宽泛
support、skip、zero-fill 或改写旧 READY 生成绿灯。

## 9. T39 退出门

T39-Repair READY 只恢复 T39 closing，不等于 T39 READY。T39 自身关闭还要求：

- production source/generated/runtime/EMI relation identities 精确等于 lock；
- 22 families 全部 implemented/closed/measured，无 partial；
- 32/32 B1 inputs reachable，outputs registered and enter B2；
- isolated GameTest PASS receipt current；
- per-group/card-only/integrated load 通过；
- main JAR 无 catalog/recovery fixture；
- `tools/t39_readiness.json#status = T39_READY` 且 `failed_gates=[]`；
- closing census 正式写出 remaining ordinary = 5,610。

在上述条件满足前不得签发 T40，不得写 T39 READY。
