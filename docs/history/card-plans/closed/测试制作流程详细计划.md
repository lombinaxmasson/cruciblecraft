## 1. 边界与禁止事项

本卡只做测试基础设施、命名空间归并、检查器和流程接线。不得：

- 删测试、取消 `required`、改成跳过、缩小任何网格；
- 为了让迁移后的测试变绿去改运行时行为（运行时 bug 登记后另开卡或按 disposition 修）；
- 用 `--write` 重刷收据或清单；
- 抬 `ModProcessingMachines` 发布预算；
- 在内容卡或当前 unique-active 里夹带本卡改动。

所有失败先登记到 `tools/waves/prep/test-authoring-workflow/disposition.json`：
`test_id`、所属网格、证据、分类（`stale_test` / `runtime_bug` / `split`）、是否阻挡。

## 2. 实施顺序

### 2.1 P0：摸底，不改代码

1. 生成 GameTest 清单：每个方法的类、命名空间、所在文件，写到
   `tools/waves/prep/test-authoring-workflow/inventory.json`。
2. 逐个命名空间新鲜跑一次（可分批），记录发现数、通过、失败、崩溃、耗时。
3. 统计每类违规的现存数量，作为棘轮基线。

P0 只产出事实，不修测试。

### 2.2 P1：共享帮手

在 `gametest/support/` 下新增，并配 JUnit / GameTest：

- `requireBlockEntity(helper, pos, Type.class)`、`requireCapability(...)`、
  `requirePresent(optional, msg)`：失败走 `helper.fail`，不抛未捕获异常。
- `fail(helper, msg)`：失败信息截断到 900 字符。
- `requireMaterialStack(material, prefix, count)`、`requirePipe(material, prefix, kind)`：
  只接受已注册物件，缺失时断言失败并说明缺的是什么。
- 机器摆放帮手：按 `Gt6SidedIo` / `MachineRelativeFace` 计算朝向，
  给出供能面、输入面的世界方向。

各测试类里重复的帮手逐步替换成共享版本；替换不得改变断言语义。

### 2.3 P2：检查器与棘轮

`tools/check_gametest_hygiene.py`，接入 `verification` profile：

1. 禁止直接强转 `helper.getBlockEntity(...)`、GameTest 中裸 `orElseThrow()` / `get()`；
2. `@GameTestHolder` 命名空间必须在 `tools/gametest_grids.json` 名单里；
3. 字面写的 `(材料, 前缀)` 夹具必须在形态权威数据里存在；
   管道夹具必须在 `PipeCatalog` 的 GT6 名单里；
4. 现存违规写进基线清单，只减不增；新代码必须干净。

检查器自身要有 Python 测试，并登记在 `python_test_policy.json`。

### 2.4 P3：领域网格

1. 按 P0 清单定出不超过 8 个领域网格（例：默认、机器、能量、物流、多方块、
   世界生成、配方内容），写进 `tools/gametest_grids.json`。
2. 把单卡命名空间迁到领域网格。只改 `@GameTestHolder` 与命名空间常量，
   不改测试体。迁移中暴露的失败按 disposition 处理。
3. `runs.gradle` 支持按网格运行；`verify.py` 按改动路径选网格。
4. `release` 跑全部网格；发现数下限从源码 `@GameTest` 计数自动算，
   替换写死的 `DEFAULT_GRID_MINIMUM = 244`。
5. 保留 `-PwaveRecipes` 作为卡进行中的临时命名空间；关卡检查要求它已并入领域网格。

### 2.5 P4：投影计数

按 VD-2026-09-003，把“我们自己数据的投影”计数改成与运行时目录或生成清单比较。
GT6 源码事实类计数保留，补上源码出处。每处改动写明前后语义。

### 2.6 不在本卡

- 拆分 `CrucibleCraftGameTests.java`：迁移命名空间后另开卡按领域拆文件。
- 修 P0 暴露的运行时 bug：登记后按各自归属处理。
