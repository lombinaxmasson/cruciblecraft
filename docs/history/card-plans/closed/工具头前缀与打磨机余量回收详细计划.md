# 工具头前缀与打磨机余量回收详细计划

> 计划 slug：`registry/tool-head-prefix-reclaim`
> 状态：已关闭 `runtime_ready` / `workflow=accepted`（2026-09-12）。
> 本文件位于 `card-plans/closed/`。
> 这是一张零 recipe-family 的 reclaim 卡：只扩充真实运行时登记权威，
> 不在已关闭的 `machines/sanding` 卡里发明替代物。

## 1. 目标与边界

打磨机 `gt.recipe.sharpener` 的 7637 条 GT6 原始配方必须逐槽保持
GT6 对象一致。原先 3781 条 overflow 分成：

- sharpener dump 中真实存在、但旧 remap 闭集没有收录的工具头；
- 已有 GT6 前缀的材料形态登记缺口；
- 已有电池物品对应的 MTE `14502` / `14512`。

本卡不创建 `gt_tool_head/*` unique item，不用板、粉、棒、vanilla item
或 `programmed_circuit` 顶替缺件，也不把打磨机标为 `player_complete`。

## 2. 真实来源

| 来源 | 用途 |
| --- | --- |
| `gt6_dump/gt6_recipe_dump/maps/gt.recipe.sharpener.json` | 提取全部 sharpener tool-head `(source_item, meta)` 与材料形态 |
| `tools/gt6_oredict_cross_reference.json` | `meta → CrucibleCraft material` 唯一映射 |
| `src/main/resources/data/cruciblecraft/materials/*.json` | 材料定义、`form_items` 覆盖和运行时形态 |
| `src/main/resources/data/cruciblecraft/energy_battery_tiers.json` | MTE 14502/14512 到现有 MV Energium 物品的 source-backed 映射 |

## 3. 实施结果

### 3.1 工具头 remap

`tools/build_tool_head_prefix_reclaim.py` 生成
`tools/tool_head_prefix_reclaim_source.json`，并把 sharpener 的真实
工具头身份并入 [`tools/tool_head_prefix.py`](../../../../tools/tool_head_prefix.py)
的单一 remap。结果：

```text
mapped                  = 13938
remainder               = 0
prefix_count            = 36
required_form_pairs     = 13938
```

所有 mapped 行均发布为 `cruciblecraft:{material}/{tool_head_*}`；
没有新的 `cruciblecraft:gt_tool_head/*`。

### 3.2 材质形态登记

`tools/build_sanding_reclaim_forms.py` 从同一 GT6 dump 生成
`tools/waves/machines/sanding/required_forms.json`，覆盖实际触碰的
13 种前缀形态：

```text
billet dust_div72 gem gem_chipped ingot lens nugget plate_gem
rock rod round small_dust tiny_dust
```

`material_form_authority.json` 以独立
`machines_sanding_required_forms` overlay 接入总登记门；`dust_div72`
和 `small_dust` 仍要求真实 `dust` 前置，未放宽为任意形态。

### 3.3 MTE

`tools/waves/machines/sanding/mte_runtime_overlay.json` 将：

```text
gregtech:gt.multitileentity@14502 → cruciblecraft:red_energium_crystal_mv
gregtech:gt.multitileentity@14512 → cruciblecraft:cyan_energium_crystal_mv
```

映射来自现有 `energy_battery_tiers.json` 的同一 `source_id`，不是新造
水晶。prep runtime audit 同时把这两个真实注册物品纳入检查。
