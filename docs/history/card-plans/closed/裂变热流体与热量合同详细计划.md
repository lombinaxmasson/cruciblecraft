## 0. 开场判断与决策

上一轮评估确认，把热流体、Reactor Jade、热交换器、蒸汽涡轮和冷却器合成一张
`player_complete` 卡会同时跨越：

- Reactor 流体与热量；
- Jade server-data 观测同步；
- HU、RU、RF、CU 等不同能量身份；
- 单体机器与大型多方块；
- 转子、背压、辐射和安全故障。

这些不是同一个最小合同。因此本卡只建立热流体与堆芯热量的稳定基础；后续卡
可以在本卡的流体 identity 和热量语义上实现设备。

```text
冷却剂输入
  -> ReactorCore 热量累积 / 衰减
  -> 独立 hot-fluid 输出
  -> 输出槽背压与停止 / 失败语义
  -> save/load 后继续同一合同
```

本卡不会因为要让测试变绿而：

- 把热锡、热钠、热重水、热氦等映射回冷流体；
- 用 `steam`、普通 molten fluid 或任意同名材料冒充 hot-fluid identity；
- 把 HU 直接乘一个未经来源证明的常数伪造成 Kelvin；
- 把 `Coolant_IC2` 或 `Thorium_Salt` 用 CC 现有材料替代；
- 注册热交换器、蒸汽涡轮、冷却器或 Reactor Jade provider。

### 1.1 Source contract rows

GT6 Reactor Core 1×1 / 2×2 的分支语义合并为同一份来源矩阵，共 11 行：

1. `Coolant_IC2 -> Coolant_IC2_Hot`；

4. 熔钠 `-> Hot_Molten_Sodium`；
5. 半重水 `-> Hot_Semi_Heavy_Water`；
6. 重水 `-> Hot_Heavy_Water`；
7. 氚水 `-> Hot_Tritiated_Water`；
8. LiCl `-> Hot_Molten_LiCl`；
9. CO2 `-> Hot_Carbon_Dioxide`；
10. He `-> Hot_Helium`；
11. `Thorium_Salt -> LiCl` 的 GT6 特殊分支。

第 1 行是外部兼容身份，第 11 行不是 hot-fluid 输出。两行仍必须在 D0
source matrix 中有明确 disposition，不能通过减少分母来隐藏。

本卡的 `player_complete` 目标分母是当前 CC 能真实拥有的 9 条转换：

- 现有蒸馏水 → 蒸汽；
- 现有半重水、重水、锡、钠、LiCl、CO2、He；

`Coolant_IC2` 和 `Thorium_Salt` 若没有 CC-owned 的准确输入身份，保持
`blocked` / `out_of_scope_external`，并记录 owner；不得用其它流体顶替。

## 2. In scope

### 2.1 流体注册与表现

- 注册 8 个独立 hot-fluid source / flowing identity；
- 保留蒸馏水 → `steam` 的既有玩家路径；
- 为 hot-fluid 固定温度、密度、黏度和可容器化语义；
- 更新材料/化学流体注册门、反向 fluid lookup、容器流体 gate 和语言；
- 从本地 `gregtech6_w` 迁入真实流体表现资源（若该表现由资源系统要求）；
- 为每次资源复制写入小型 art manifest；
- 缺少本地来源资源时保持该 identity blocked，不借用现有熔融流体或机器贴图。

### 2.2 ReactorCore 热量合同

- 将 `ReactorCoolant` 的输入、单位热量、热衰减 divider 和输出 multiplier
  改为来源矩阵驱动；
- 对 1×1 / 2×2 使用同一份转换合同，不复制两套容易漂移的分支；
- 保持每种冷却剂对燃料棒中子行为的已有 source-backed 差异；
- 热量消耗必须先模拟冷却剂 drain 与 hot-fluid output fill，再一次性提交；
- 输出槽满、冷却剂不足、hot-fluid identity 缺失时不得静默丢流体或生成错误身份；
- 保存 / 读取 heat、lastHeat、冷却剂槽、输出槽、running/stopped 和 rod 状态；
- 对现有 `destroyRods()` 失败语义做来源核对，明确其是保留、改为停止，
  还是另由安全卡接管；不得让背压结果继续隐式决定玩家损失。

### 2.3 温度与熔毁决策门

本卡必须冻结“热量”合同，但不允许在没有来源的情况下直接把 HU 换算成 K。

D0 必须给出以下二选一：

1. 找到 GT6 / 当前 CC 已存在的温度与熔毁映射，写入 source-backed 或
   source-derived 数值并实现；
2. 明确 `temperature_k`、`meltdown_at_k`、辐射和烫伤不属于本卡的可用字段，
   将它们标为后续观测/安全卡的 blocked contract。

无论选择哪一项，都不能使用“HU × 常数”的未经证明实现。Reactor Jade
不得在本卡中提前读取或显示虚构的温度字段。

## 5. 实施阶段

### A. D0 来源矩阵与身份门

生成 `tools/waves/runtime/fission-hot-fluids/d0_hot_fluid_source_matrix.json`
前不得修改 Reactor runtime。每行至少包含：

```text
source file / source line
source coolant identity
CC input registry identity
hot output registry identity
input units / EU_PER_UNIT
output units / multiplier
heat divider
backpressure behavior
save/load fields
disposition = ready | blocked | out_of_scope_external
```

D0 必须同时核对：

- 1×1 与 2×2 源码分支是否完全一致；
- `Coolant_IC2` 是否有合法外部兼容 owner；
- `Thorium_Salt` 是否有真实 CC 输入身份；
- 氚水是否能从当前材料/流体注册门生成真实输入；
- 当前 `ReactorCoolant` 的数值是否与本地 GT6 源一致；
- hot-fluid identity 是否会与已有 molten / chemical fluid registry 冲突。

任何缺失输入、输出或来源资源都进入 blocked ledger；不得生成 stand-in
配方或把冷流体复用为热流体。

### B. Hot-fluid registry

先完成 8 个独立 hot-fluid 的 registry、流动流体、属性、反向查找、容器
和语言，再接 Reactor。每个 fluid 要有：

- source / flowing pair；
- source material / GT6 identity；
- 温度、密度、黏度和状态来源；
- bucket / container 行为的明确 disposition；
- 资源 manifest；
- client / server lookup 测试。

### C. Reactor conversion

将 `ReactorCoreBlockEntity.convertCoolant()` 改成 contract-driven conversion：

1. 读取已识别的冷却剂；
2. 根据 source matrix 计算本 tick 可消耗单位；
3. 模拟输入 drain 和输出 fill；
4. 输出空间不足时保留热量与输入状态；
5. execute 后同时更新 heat、lastHeat、两侧流体和持久化 dirty state；
6. 同一 tick 不允许重复消耗或重复产生 hot fluid。

不得把 1×1 / 2×2 复制成两套转换表；堆芯差异只来自 slot topology。

### D. Runtime / save-load / regression

- 热流体转换与原有 46 棒参数、邻接中子和棒转化保持隔离；
- 蒸馏水 → 蒸汽路径必须保持兼容；
- 热锡 / 热钠的 heat divider 与普通冷却剂差异必须有回归断言；
- 输出背压、冷却剂不足、空堆芯和 reload 逐项测试；
- 旧世界只有冷流体、旧 output identity 或缺少新字段时采用显式 migration
  / quarantine，不静默解释为另一种流体。

### E. Closeout

只有 `cc_owned_conversion_rows = 9 / 9 exact`、8 个 hot identity 全部真实
注册、存档/背压测试通过且 blocked ledger 只剩明确外部兼容项时，才允许签发
`energy/nuclear-fission-hot-fluids` capability。

机器可读 `unique_active_wave` 在实现开始后才设为
`runtime/fission-hot-fluids`；关闭时恢复 `null`。本卡不重新写
`nuclear_started`。

## 7. BLOCKED / 撤回

必须保持 blocked：

- 任何 hot fluid 只能通过普通 molten / chemical fluid 冒充；
- `Coolant_IC2` 或 `Thorium_Salt` 缺真实身份却被塞进其它冷却剂；
- current `ReactorCoolant` 数值没有完成 GT6 source replay；
- 输出槽背压会静默丢输入、热量或 hot fluid；
- save/load 后 hot output 被识别成冷流体；
- 为了显示 Jade 或温度而发明无来源 Kelvin / meltdown；
- 为了本卡顺手注册热交换器、涡轮、冷却器或 RF/CU。

撤回时保留 D0 source matrix 和 blocked ledger；不要删除已经确认的真实
fluid identity，也不要把未完成行改写为普通冷却剂。撤回不得修改上一张
`energy/nuclear-fission-survival` 的 closed seal。
