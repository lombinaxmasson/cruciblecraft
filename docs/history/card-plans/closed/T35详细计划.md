### 2.2 Disposition 与 priority 分列

T35 current disposition：

```text
implemented
planned
deferred
out_of_scope
```

priority：

```text
P0 = 推进阻塞或所有 P1 的有界前置
P1 = 已有/可复用 host、高工业复用、玩家路径可闭合
P2 = 可选；只有累计 load 上界仍低于所有 soft budget 才能进入工作集
P3 = 跨模组、核/G10、巨大组合或当前不适合批量实施
```

规则：

- `implemented` 仍必须有 closure/fidelity/load evidence；
- `planned` 必须有唯一 owner 和 machine-verifiable replacement；
- `deferred` 必须有 owner、reason、replacement、recheck；
- `out_of_scope` 必须有产品排除理由；
- priority 不能替代 disposition；
- 使用字段名 `portfolio_priority`，避免与 `CC-4.5-P0` 等历史 issue id 混淆。

## 5. R1 · `T32-VD-001` 受保护 preflight

### 5.1 根因

`tools/build_t5_chemical_readiness.py` 当前把 `.gitignore` 放进：

```text

```

测试也把它锁定为必需 key。`.gitignore` 不是 T5 chemical semantic input。

### 5.2 允许修改

```text

tools/tests/test_build_t5_chemical_readiness.py
tools/t5_chemical_readiness.json
tools/known_issues/verification-debt.json
```

若需要受保护模式，可在 T5 builder 增加显式的 source-metadata rebase guard；不得写一次性
临时脚本。

### 5.3 受保护算法

1. 从 builder 的 source_hashes 定义移除 `.gitignore`；
2. 同步测试，明确 `.gitignore` 不再是 semantic/currentness key；
3. 运行完整 `build()`，不是 `reference_only_check()`；
4. 比较 candidate 与 committed ledger：
   - 先剥离整个 `source_hashes`；
   - 其余 JSON 必须字节语义全等；
5. 允许变化的 metadata 仅：
   - 删除 `source_hashes.gitignore`；
   - builder 自身 hash；
   - 因 builder hash 直接派生的声明字段；
6. 任一 counts、chemical materials、template coverage、blockers、recipe replay 变化即停止；
7. 由 builder 写 ledger；
8. 运行 T5 定向测试；
9. 运行严格 recipes integration；
10. 只有 recipes profile 退出 0，才把 `T32-VD-001.status` 改为 `closed` 并记录证据。

### 5.4 验证
