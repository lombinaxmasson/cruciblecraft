## 0. 决策

原版替换 R0 已关闭为 `VANILLA_REPLACE_R0_READY`。第四轨
`portfolio/large-content-branches` 的前两个命名切片（非矿 worldgen、
vanilla replace）都已做完 R0 判定，均为 `requires_new_runtime`。下一张
不得签那些实现 child，也不得签 count-ceiling、combinatorial 或核能。

兴趣不是分母。growth-order 点名了 `crops/food/bees`，对照图展开为三行。
「搬全、回头不想要再删」的合法读法是：三类一起冻结，不把蜜蜂拆出去；
R0 仍然不写配方。以后 realization 卡可以把某一类标成 `out_of_scope`，
不得在本卡假装已经种田、榨汁或养蜂。

整轨仍不是一张卡。先签最小可审查切片：

```text
portfolio/crops-food-bees-r0
```

它只回答：这三类能否由**已有** CC 机器 / 导入器 / worldgen catalog 作
有界扩展承载，还是必须另开 RecipeMap、作物运行时或蜂箱 worldgen。
R0 READY 不等于 13,373 条 dump 配方进 production，也不等于 T35 已排除
的 juicer / fermenter / squeezer / hive MTE 收回，更不在 topology
预分配实现 child。

## 1. 完成后应该成立的工作流

```text
pinned capability-map crops/food/bees rows (3)
  + dump maps recipeCount as scale, not census
  + other_features plant.* (2) and WorldgenHives (10)
  -> inherited_denominator.json
  -> source_semantics.json
       crops = plant worldgen + squeezer map, not wood recipes
       food = juicer / fermenter maps, not smelter
       bees = hive worldgen + bumblequeen / bumblelyzer
       plantalyzer recipeCount=0 is not a census
  -> existing_mechanism.json
       no CC squeezer / juicer / fermenter / bumble host
       T35 excluded those MTEs from the 1.x machine tree
       generic importer does not create new RecipeMaps
       WorldgenHives were remainder of non-ore R0, not owned there
       count-ceiling / kind envelope still report-only
  -> crops_contract.json
       what a later implementation card must answer
       what R0 must not invent
  -> feasibility.json
       per category:
         bounded_extension
         | requires_new_runtime
         | defer_to_portfolio
         | blocked
  -> CROPS_FOOD_BEES_R0_READY
       or BLOCKED / DEFERRED with missing evidence named
```

关键分界：

1. R0 不写 Java、不注册新 RecipeMap、不改 `worldgen_catalog/**`、不跑
   GameTest、不签 production lock、不写 `src/recipe_generated/**`。
2. dump 配方数只作规模上下文：squeezer 5322、juicer 96、fermenter 6435、
   bumblequeen 80、bumblelyzer 1440，合计 **13,373**。`owns_families` 仍
   为 0，不得写成 census complete。
3. `gt.recipe.plantalyzer` 的 `recipeCount = 0`，不得手填假分母。
4. `WorldgenHives` 10 条与 `plant.*` 2 条从非矿 worldgen remainder 172
   划入本卡；其余 160 条 dump 特征仍不拥有。
5. T35 排除的 juicer / fermenter / squeezer / bumble hive MTE 不是本卡
   实现对象；只读对照。
6. 只有某类对照到**具名现有** CC runtime 且判定 `bounded_extension`，才
   允许**另签**该类 implementation child；本卡 topology 的后继保持未分配。
7. capability map / sealed growth-order / 已关闭 vanilla-replace 与
   non-ore-worldgen seal 在 R0 只读。

## 5. 契约与可行性

`crops_contract.json` 只冻结后续实现卡必须回答的问题，不实现它：

```text
disposition_policy   per-category implemented | planned | deferred | out_of_scope
new_recipe_maps      squeezer / juicer / fermenter / bumble* 是否新 kind
crop_runtime         plant.* 生长 vs 又一行 scatter JSON
hive_worldgen        10 个维度 hive vs T20 overworld-only
player_acquisition   生存如何遇到作物 / 食物 / 蜜蜂
scale                13,373 dump 行如何切 production lock
fail_closed          未知 plant / hive / food map 不得 silent no-op
delete_later         某一类 later out_of_scope 时如何保留本卡 hash
```

`feasibility.json` **按类别**取值：

```text
bounded_extension     该类可由具名现有 CC runtime 有界扩展承载
requires_new_runtime  必须另开 RecipeMap、作物生长或蜂箱 worldgen
defer_to_portfolio    合法去向是另一个已命名 portfolio（本切片预期不用）
blocked               缺 dump、缺 schema、或缺测量计划
```

只有 `bounded_extension` 才允许另签该类 implementation child。
`requires_new_runtime` 不得在本卡 topology 预分配实现后继。
R0 仍可 `CROPS_FOOD_BEES_R0_READY`：只证明分母和逐类 verdict current。

预期（预读，实施时必须用证据重放，不得手填）：三类目前都是
`cc_mechanism = none`。Food 与 Bees 很大概率 `requires_new_runtime`
（新 RecipeMap + T35 已排除 MTE；hive 还撞 T20 overworld-only）。
Crops 即使有两行 `plant.*`，若缺口是作物生长而不是 scatter JSON，
仍应 `requires_new_runtime`。不得把 13,373 条 dump 行写成
`bounded_extension` 的理由。

## 8. 撤回

实施中发现阻塞时只有三种合法结果：

1. 在本卡内补齐验收证据；
2. 保持 `BLOCKED`，写清缺的是 dump、schema 还是测量计划；
3. 正式撤回并重签，保留旧 denominator hash。

不得用「先写一点 squeezer 配方再补契约」绕过 R0。不得把 13,373 条 dump
行写成 GT6 作物/食物/蜜蜂完成。不得把导入器 READY 或 T20 矿脉写成已经
覆盖 plant.* / juicer / hive。某一类以后不想要，走 realization 卡的
`out_of_scope`，不在本 R0 假装没点名。

关闭时：本计划移到 `card-plans/closed/`，补 stage archive 与 work log
收口；更新 history index、roadmap、workflow 与 verification；不重写已
sealed 的 growth-order JSON；不自动创建 Git commit。
