# T40 详细计划

> 阶段：T40 · Electrolyzer bounded recipe wave
> 性质：T39 之后第一张 Electrolyzer production-lock wave
> 状态：✅ 已关闭（2026-08-26）；`T40_READY`
> 固定 GT6 revision：`3703e40308c8c030763fd6297dea8b210d2a77b1`
> 前置：`tools/t39_readiness.json#status = T39_READY`，`failed_gates=[]`
> opening ordinary gap：5,610 families
> catalog fixture：Electrolyzer 61 families / 151 source rows（test-only，不是 READY 分母）
> production lock：13 families / 22 relations；combinatorial `#0000`/`#0001` BLOCKED

> 后继：T41 仅保留连续编号，不预分配 host/family；`unique_active_card = null`

权威流程是 [ordinary recipe wave 流程与规范](../../../current/recipe-wave-workflow.md)；
本计划只记录 T40 的选择、风险、输入和额外约束，不重复该流程的通用实现细节。Markdown
不能代替 work set、source receipt、production lock、load measurement、census、topology
或 readiness。

## 1. 签发边界

T40 选择 `cruciblecraft:electrolyzer` 作为候选 host，原因是它已注册且可运行，剩余
ordinary_optional catalog 规模为 61 families / 151 rows，能够先验证 Electrolyzer 的
compact/shard 路径，而不把 Smelter、Bath 或 Mixer 的大体量长期债务混入首张后继卡。

在真正签发前，重新从当前 census 输入计算以下 catalog：

```text
source = tools/t35_recipe_families.json + tools/t22_5_row_classification.json
filter:
  cc_host_map = cruciblecraft:electrolyzer
  classification = ordinary_optional
  membership_kind = semantic_template
order:
  template_key ascending
```

此 rule 的预期结果为 61 complete families / 151 source rows。R0 必须把准确
`selection_sha256`、family IDs、template keys、stable IDs 和 source revision 写入
`tools/t40_work_set.json`；若重算结果变更，本草案只说明候选 host，不授权沿用旧计数。

T40 在 R0 完成前仍未正式签发，保持：

```text
unique_active_card = null
next_issue_id = T40
preassigned host/families in closing topology = false
```

R0 work set、catalog source receipt 和 topology issuance 完成后，T40 才成为唯一 active
内容卡；此时任何失败 family 不得被另一 family 静默替换。

## 2. Catalog、candidate 与 production lock

```text
catalog fixture
  expected 61 families / 151 relations
  authority = source replay、codec/router capacity test only

candidate selection
  dynamic result after fidelity、operand、player-path and representation audit
  authority = diagnostic only

production lock
  reviewed family-atomic subset of candidate
  authority = production generation, runtime, load, census and readiness
```

完整 catalog 位于 `src/test/resources/t40_catalog_fixture/**`，不能进入 main resources，
也不能成为 production equivalence、load winner、player-path 或 census evidence。

Production lock 至少绑定 family/template/stable IDs、catalog selection hash、source
revision、production family/relation counts、support IDs/hash、B0 baseline、publication
groups、shard aggregate root 与 phase-deferred ledger。普通生成命令不得因 candidate 漂移
而重写已存在 lock；任何重签必须显式审批并重建下游 receipts。

Gap 只能扣除 lock 中已完整关闭的 family：

```text
remaining ordinary
  = 5610
  - completed locked families
  - formally reclassified families
```

重分类必须有明确 future owner，单独列账，不能伪装为 implementation completion。partial
family、blocked family 与 fixture-only family 都不扣 gap。

## 3. 已知范围和风险

Electrolyzer catalog 的预期结构为：

| 分类 | Families | Relations | 约束 |
| --- | ---: | ---: | --- |
| singleton exact | 34 | 34 | 可作为优先审计对象，但仍须逐 relation 证明 |
| small multi | 25 | 82 | 每 family 2–7 rows；必须 family-atomic |
| large combinatorial | 2 | 35 | `#0000`=20、`#0001`=15；先证明 enumeration/slot/shard，否则 BLOCKED |

现有 T5 chemical Electrolyzer 有 62 条配方，其中只有 11 条、7 个 template family 与
本 catalog 发生关联；54 families / 123 rows 没有 T5 runtime 覆盖。T5 不是 T40 fidelity
或 player-path 的替代证据。

任何 T5 与 T40 relation 的 input/output signature 完全等价时，才允许在 loader 中由
T40 明确 supersede；否则 T5 row 保持发布，T40 不能 co-publish 相同 signature 或借模板名
推断等价。运行时必须继续执行 unique-ID 和 no-shadow 验证。

T40 的 T14 opening 来自 `tools/t39_readiness.json#t40_opening`：

```text
datapack_authored_entries = 3720
eager_publication_rows   = 16659
lazy_logical_rows        = 2366
lazy_cache_ceiling_rows  = 56
lookup_candidate_count   = 73  (soft 64 已超，hard 128 未超)
lookup_p95_ns            = 685725
```

所以 151 relations 绝不能默认整体发布。每个 group 和 integrated current 的 routed candidate
interval 都必须不超过 128；不得提高 T14 或 shard hard ceiling 来制造通过。Gem/mineral
dust、clay/salt/nitrate precursor、fluid input、byproduct sink、未注册 form 以及 post-1.x
material 都是 R0/R2 的实际审计对象，而不是用 namespace 或已注册 ID 掩盖的假定可达项。

2. 生成并以 `--check` 验证：
   - `tools/t40_work_set.json`；

   - `tools/t40_electrolyzer_source_review.json`；

3. 逐项生成 `tools/t40_operand_disposition.json`，只允许
   `proven_equivalent` 或已经实现的 `needs_current_expression` 进入 candidate；其余记录为

4. 生成动态 `tools/t40_candidate_selection.json`。同 family 任一 relation 失败 fidelity、

5. 为 `#0000/#0001` 决定 exact expansion 或 parameterized representation；没有全 logical

   BLOCKED。
6. 人工冻结 `tools/t40_production_lock.json` 和 schema。lock 生成后，所有下游 builder
   只读取 lock，不读取 candidate 来决定 production。

## 6. R2 · 分层玩家路径与形态门禁

固定三层：

```text
B0 = current T21 typed closure + closed T37/T38/T39 production
     without T40 production/support
B1 = B0 + production-lock-owned minimal T40 support
B2 = B1 + T40 production relations
```

R2 生成 `tools/t40_player_path_support.json`、`tools/t40_layered_player_path.json` 与
`tools/t40_required_forms.json`。Support 仅可解决 lock relation 的反向依赖，并要求加入前
输入已在前一层可达；Electrolyzer target relation 不得自证其自身输入。

每条 production relation 必须记录 item/fluid consume、preserve/catalyst、来源、output
downstream 或 terminal use；B1 输入 100% 可达、输出已注册并进入 B2 才能进入生产。需要
新 material form 时，只能使用 factual form、source-backed acquisition 或本卡显式 extras；
不得放松 material registration gate。

## 7. R3 · Publication groups、shards 与等价

在 policy/measurement 前声明以下候选 group；最终 manifest 只包含 lock 实际拥有的 group：

```text
cruciblecraft:t40_electrolyzer_singleton
cruciblecraft:t40_electrolyzer_multi
cruciblecraft:t40_electrolyzer_combinatorial
```

生成 `tools/t40_publication_group_manifest.json`、`tools/t40_shard_manifest.json`、
`tools/t40_runtime_dependency_manifest.json`、runtime-map 与 equivalence ledger。route key
只能使用 query-visible consumed item/tag identity，且仅在真正可选择时加入 fluid input；
不得使用 EUt、duration、priority、stable-id hash 或文件分卷。

Broad tag 或无可用 index adapter 的 relation 必须进入显式 overflow shard。任何 normal
shard 或 overflow shard 大于 128，或 query 不能无全 shard 扫描导出候选集合时，publication
fail closed。

测试分为：

- production suite：lock 精确 N/M、stable IDs、group/shard membership、完整 relation
  enumerate/match/reject、T5 supersede 与 no-shadow；
- catalog fixture suite：61/151 replay、codec/router capacity；fixture 结果不得影响
  production policy 或 census。

## 8. R4 · Materialization、load 与 GameTest

在运行测量前，`tools/t40_materialization_policy.json` 必须对每 group 预先声明 immediate、
on-demand、hybrid、cache ceiling、hybrid boundary 和 tie-break。不得复制 T37/T38/T39 的
winner 或 cache 比例。

新增 Electrolyzer measurement harness，至少测：

1. 每个 publication group 的 card-only 1x；
2. T40 card aggregate 1x；
3. T14 + T37 + T38 + T39 + T40 的 integrated current；
4. 每个候选的 server/dedicated-client reload/index、enumeration、lookup/reject、sync、
   retained memory 与 allocation，多样本 p50/p95。

correctness/equivalence、hard ceilings、cumulative soft-budget interpretation、预声明
tie-break 的顺序不可颠倒；5x/20x 只作诊断，不能填充未测量的 1x 指标。

新增 `T40RecipeGameTests.java` 和 `-Pt40Recipes` 执行入口。GameTest receipt 必须绑定
production lock、support、publication/shard aggregate、runtime dependency manifest、
测试 namespace/IDs 和新鲜 committed UTF-8 log；scratch run directory 不是证据。
