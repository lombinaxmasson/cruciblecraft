# T33 详细计划

> 阶段：T33 · 地表石子可达性闭环
> 状态：执行中；T33 是唯一 active 内容卡
> 依据：[当前路线](../../../current/roadmap.md) 与 [验证指南](../../../current/verification.md)
> 不包含：岩层替换、矿脉指示岩、逐材质石子平衡、玩家发行、RC soak 或 GA

## 目标

让 `SurfaceRockFeature` 的实际 runtime 放置成为可审计的生存 S0 来源，使
`rock_pack.json` 的 `c:rocks` 输入可达，并以 T33 superseding record 关闭
历史 `CC-4.5-P4`。

## 实施边界

1. 以 `worldgen_catalog/surface_scatter.json` 声明现有 configured feature、
   placed feature、Overworld biome modifier、`top_layer_modification`、`c:rocks`
   动态 tag 与 material-gate rock 域。
2. `build_worldgen_catalog.py` 只校验该声明与 hand-authored runtime JSON；不得生成
   surface resource、改变 T20 `underground_ores` biome modifier，或改变 263 / 274 /
   129 的历史 catalog 计数。
3. `GeneratedMaterialPack` 继续是 `c:rocks` 的 runtime block/item tag 来源；
   GameTest 必须从真实 registry 验证 tag 与放置，reachability 不依赖静态 tag 文件。
4. S0 只根据声明引用的 material registration gate 中 `rock` form 重建 concrete
   block-item seed，禁止泛化为任意 tag seed。
5. T26 known-issues ledger 保持冻结；在 T27 portfolio 中以 T33
   `closed_open_item` supersede `CC-4.5-P4`。

## 关闭判据

### Closure

- runtime `c:rocks` block tag 非空，成员均为 `RockBlock`，对应 item tag 与 block item
  域一致；
- registry-resolved `surface_rock_scatter` 在 prepared chunk-aligned dirt/sand surface
  至少真实放置一个 `RockBlock`，且不覆盖非空气方块；
- declaration、configured/placed feature 和 biome modifier 完全一致；
- T33 S0 seeds 可重建；`rock_pack.json` 不再含不可达 `c:rocks` operand；
- portfolio 将 `CC-4.5-P4` 记为 closed supersession，T26 历史条目不被重写。

### Fidelity 与载荷

- `SurfaceRockFeature` 保持独立地表散布；不会声称等价于 GT6 大矿脉；
- rarity、tag、biome step 与 S0 来源在声明中固定；
- 无新矿脉、方块/物品注册、配方 publication 或 T20 catalog 分母变化。
