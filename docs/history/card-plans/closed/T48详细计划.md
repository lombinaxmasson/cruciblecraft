T48 的 Bath 尾账候选、`N<300` 例外、非 block identity/form 闭包、以及 T47-VR 之后的

unmapped/vanilla 对象。本卡不切 Mixer，不用其它 host 凑 300，也不承诺用 filler 或放宽
hard gate 强行 `N=150`。

### 0.2 `N < 300` 例外（R0 必须写入 lock / readiness）

[workflow §2.1](../../../current/recipe-wave-workflow.md) 默认 production lock
`N >= 300`。本卡合法例外的理由是：

1. **Bath 未清零前不切 Mixer。** T47 / roadmap / workflow 已把这条写成硬顺序。用 Mixer
   或其它 host 凑 300 会直接违反该顺序，也违反同 host 语义同质。
2. **余下 Bath ordinary 宇宙就是这 150 个 family。** T47 已锁走一切不依赖新 identity
   kind 就能闭合的 Bath family（395）。剩下的不是「Bath 里随便切的小切片」，而是
   Bath remainder 全集。
3. **它们共享同一类基础设施 blocker。** 150/150 都停在 `identity_or_operand` +
   `object_identity`；47 个另含 `material_form`，26 个另含 `b0_acquisition`。T47
   identity catalog 只有 `kind=block`。不解这些 identity/form，这 150 个 family 无法
   进入任何合法 lock。

例外必须写入 work set、production lock 和 readiness，列出：

```text
exception_kind            = bath_host_remainder_identity_closeout
candidate_family_ceiling  = 150
candidate_relation_ceiling = 34186
minimum_N                 = 1 complete semantic cohort（不是 300）
padding_hosts_forbidden   = Mixer / Smelter / 其它
```

这不是「即将 gap=0 的最终尾账」：即使 `N=150`、`R=0`，closing gap 仍为 1,349。1,349
是其它 host / deferred ledger 的事，不是本卡用 Mixer 填进去的许可证。

若 R0 无法关闭任一完整 identity cohort，保持 BLOCKED 或正式撤回；不得用 unresolved
operand、partial relation 或其它 host 补数。

### 0.4 本卡签发边界

R0 对 150 个 candidate family 逐族只产生一种 outcome：

```text

  = 全部 source relations 可重建，identity/form/B0/fidelity/load 已闭合

  = family-atomic 证据证明属于明确 future owner；单独计 R，不计 completion

  = 仍缺 identity / object / form / B0 / fidelity / load
```

目标是 Bath remainder 清零（`N=150`、`R=0`、Bath ordinary 不再留在 gap）。这是目标，
不是预写 lock。未通过的 family 留在 current gap；Mixer 评估继续禁止，直到 Bath
remainder 为 0。

## 1. R0：Source Pack、blocked 重放与 production lock

### 1.1 Source Pack

T48 必须新建独立、可重放的 Bath remainder Source Pack：

```text
tools/t48_bath_source_pack_manifest.json
tools/t48_bath_source.json
tools/t48_bath_source_receipt.json
tools/t48_bath_source_review.json
```

Source identity 至少固定 source_system、source_revision、source recipe identity、
semantic family identity、relation stable ID、source row hash、representation、
shadow order、全部 item/fluid operands。Full replay 从 pinned GT6 oracle 取得；
oracle 缺失、dirty、revision 不符或 source row 无法重建时 fail closed。日常
`--check` 验证已提交 normalized source 与 receipt，不把 `SKIPPED` 当 PASS。

差集必须同时满足：

```text
family_id ∈ T47 blocked set
family_id ∉ T46 lock ∪ T47 lock
host = cruciblecraft:bath
source relations rebuild to 34,186
```

不得用 owner 数量、文件名范围或「T47 没锁的 Bath」口语差集代替 source replay。

### 1.2 Work set 与 candidate

```text
tools/t48_work_set.json
tools/t48_bath_candidate_selection.json
```

Work set 是 source-complete 150-family universe。Candidate 可随当前 identity/form
诊断重算，但不具生产权威。每个 family 至少记录 family_id / template_key、source
relation count、representation、current_owner、blocking_axes、unique_kinds、
missing item/form identities、B0/B1 状态、candidate outcome。

禁止复用：

- T46 `unique_kinds == ["mte"]` 与 `cruciblecraft:t46_bath_mte`；
- T47 `kind=block` catalog 冒充 tool_head / multiitem / prefix 已闭合；
- T47 publication groups `t47_bath_exact` / `t47_bath_exact_multi` 扩写。

### 1.3 Identity / form 是本卡的关键路径

T48 不能再把 identity 当成「顺手映射」。R0 必须先按 kind 建立可关闭的 identity
authority，再决定哪些 family 能进 lock。最低 kind 集合：

```text
tool_head
multiitem
gt_prefix:*          （含 crushedPurifiedTiny、ingot*、plate*、gem*、lens 等）
unmapped / vanilla   （empty unique_kinds 与 registry_proof/vanilla 对照）
material form        （47 个 material_form 轴；只写 t48_required_forms.json）
```

每个 source identity 只能有一个 canonical resolver winner。禁止：

- 按数字范围、显示名或字符串后缀猜 runtime ID；
- 把 behaviorally distinct 对象合并成无 component 区别的别名；
- 输出 `gregtech:*` / `gregapi:*` runtime ID；
- 用注册成功、namespace allowlist 或创造栏可见冒充玩家可达；
- 用 T46 `gt_mte/*` 或 T47 `gt_block/*` 代替 tool_head / multiitem / prefix；
- 带 `tool_head` / `multiitem` / GT prefix 标签就算对象已表达。

`tools/t48_required_forms.json` 由全局 material/form authority 汇总；card builder
不得直写历史 material gate。每个 required form 必须证明 item registration、
model/display、source mapping 和玩家取得。

### 1.4 Production lock

只有人工审核后的 `tools/t48_production_lock.json` 可以驱动 compile、runtime、load、
census 与 readiness。Lock 必须固定 N/L、family IDs、stable IDs、source row hashes、
representation breakdown、identity/form roots、support tree、publication-group
assignment、`N<300` 例外字段、T47 opening roots。

签发计划不预写精确 `N`、`L`、family IDs、group IDs 或 winner。允许的上限是 150 /
34,186。R0 freeze 后不可静默替换；任一 locked family 失败时，只能保持 BLOCKED 或
正式撤回重签。

可以按**完整 identity kind cohort** 锁子集（例如 tool_head 36 个 family 全过、
multiitem 未过，则只锁 tool_head）。禁止切开 family，禁止按 relation 抽样。

### 1.5 明确不属于 T48

- T46 803 Bath MTE families 与 T47 395 remainder families；
- Mixer、Smelter、Centrifuge 或其它 host；
- 已在 deferred ledger 的 1,817 个 `later:recycling` families；
- GT6 MTE mutation dispatcher；
- 用 `ParameterizedSpec` 掩盖未完成 identity/operand 映射；
- 无 query-visible key 的全 Bath scan；
- 玩家发行、RC soak、GA 或 nuclear scope。

Bath remainder 未清零前不切 Mixer。T49 不在本卡预分配。

## 8. 签发、撤回与关闭纪律

- unique active 内容卡为 T48；
- opening 只来自 T47 closing gap 1,499 与 15-group T14 remeasurement；
- 150 / 34,186 是 R0 candidate，不是预承诺 production lock；

- host 仅为 `cruciblecraft:bath`；
- forward-v2 只追加 T48 delta；
- T47-VR seal/receipt 合同对本卡强制；
- T49 当时不预分配；随后已达到 `T49_READY`：[T49](T49详细计划.md)；
- 本次签发动作不创建 Git commit。

合法撤回条件包括：

- R0 不能复现 150 / 34,186；
- 无法关闭任一完整 identity kind cohort；
- 任一 locked family 无法关闭 identity/form/B0/fidelity；
- exact_multi router 出现无法有界的 overflow/full scan；

- T47 closing、T47-VR seal 或 forward-v2 base 漂移。

撤回必须保留 source/candidate root、旧 selection hash、失败 family/identity/group
与原因。

关闭后：

1. 将本文件移至 `card-plans/closed/`；

3. 写 `t48_closeout_seal.json`；更新 history index、roadmap 与 workflow；

5. 若 Bath remainder 仍 > 0，T49 仍从剩余 Bath 重开；Bath 清零后才能评估 Mixer；
