Bath；若合法 lock 低于 300 families，必须撤回并重签，不能为了保留编号伪造 completion。

## 2. Identity、fluid、form、B0 与 disposition

### 2.1 非 MTE identity authority

T47 必须按 production lock 实际需要建立新的 exact identity/operand authority。允许按
语义域拆分 catalog，但每个 source identity 只能有一个 canonical resolver winner：

```text
block / BlockItem
multiitem
tool head
GT prefix object
material/form item
fluid
other exact object identity
```

每个条目至少记录 source identity、source evidence、CC runtime ID、registry kind、
behavior/display requirements、acquisition authority、mapping class 与 occurrence counts。
禁止：

- 按数字范围、显示名或字符串后缀猜 runtime identity；
- 把多个 behaviorally distinct source objects 合并为无 component 区别的别名；
- 输出 `gregtech:*` / `gregapi:*` runtime ID；
- 把注册成功、namespace allowlist 或 creative tab 可见冒充玩家可达；
- 用 T46 `gt_mte/*` item 代替非 MTE object。

### 2.2 Fluid 与 form

T47 fluid mapping 必须以 T22.5 + T46 forward-v2 closing 为 base，仅追加 lock 所需的新
mapping。每个 fluid 固定 semantic category、amount unit、runtime ID、registration、
container/source path 与 B0 state。不存在合法映射时注册明确 CC fluid；不得用 water 或
任意已有流体占位。

本卡只写 `tools/t47_required_forms.json`。全局 material/form authority 负责汇总与注册门禁，
card builder 不得直接改写历史 material gate。每个 required form 必须证明 item registration、
model/display、source mapping 和玩家取得。

### 2.3 B0/B1 support

无法由 T46 cumulative typed closure 直接取得、但可由有限当前内容闭合的输入，可以进入
T47-owned B1 support。Support 必须：

```text
input reachable before route
output belongs to a locked reverse dependency
source-backed or explicit DESIGN_POLICY
finite and countable
present in generated/runtime resources
included in authored/eager/load accounting
bound by GameTest receipt tree hash
```

禁止只有 declaration JSON、namespace 前缀或测试注入而无真实运行时 recipe/worldgen。

### 2.4 Recycling / treatment disposition

T47 必须为 production lock 全集逐族写 disposition。若 R0 证明某 family 是真正 recovery /
recycling / post-1.x content，可进入 reclassified outcome；要求所有 relations 的 input/output
transition 与 future owner 一致。

```text
completion_delta       = N
reclassification_delta = R
```

`R` 不得混入 `N`。既有 deferred 1,817 在 opening 保持只读；只有 T47 新证明的 family 才能
按独立 evidence 增加 deferred closing，不能因为 owner 名称或 treatment 字样批量重分类。

## 4. Publication groups、shards 与 materialization

### 4.1 Group derivation

T47 不把 47,894 relations 直接并入 `cruciblecraft:t46_bath_mte`。R0/router dry-run 必须先按
production lock 的 representation 与 query-visible semantic domain 派生新 groups。

默认架构：

1. exact relations 可形成独立 low-density group；
2. exact_multi relations 按 dominant item/fluid/form/component query signature 拆为一个或
   多个 groups；
3. 每个 group 独立 policy、cache、shard manifest 与 measurement；
4. 同一 `cruciblecraft:bath` target 原子 reload/publish，跨 group 保留 global shadow order。

`exact` / `exact_multi` 是起始 partition，不是充分的 semantic routing key。若一个
exact_multi mega-group 无法将 routed candidate interval 保持在 soft/hard envelope，必须按
query-visible semantic domain 继续拆分。不得按 family 序号、文件大小、stable-id hash 或
“每 N rows”盲切。

### 4.2 Query-addressable shards

沿用已验收的 routing contract 时，每条 relation 的 route key 只能来自 query 可直接提取的：

```text
target map
consume/preserve/catalyst item or tag
fluid identity
component/config identity
query-visible input shape
```

每条 relation 至少属于一个 deterministic shard；query 必须能在不扫描所有 shards 的情况下
推导候选 shard。记录：

```text
group/shard count
relation membership
overflow count
worst shard size
routed candidate p50/p95/max
unrelated-query rejection
aggregate shard root
```

Overflow/unindexed 必须显式；超过 candidate hard ceiling 128 时 fail closed，不能退回全
Bath scan。从 T47 起，soft 64 只警告、不淘汰；hard 128 才是阻塞门。on_demand 若把
routed candidate max 保持在 1，exact_multi mega-group 可以保留，不必为 soft 超线拆组。

### 4.3 Policy-before-measure

每个 group 在测量前冻结：

```text
immediate candidate
on_demand candidate
hybrid candidate
cache ceiling
hybrid eager selector
correctness gates
tie-break order
```

Immediate 可以保留为 diagnostic candidate，但 47k relation 不能假定 eager 可行。
On-demand/hybrid 是预期生产候选，仍必须由实测决定。禁止复制 T46 的 zero-eager selector、
cache 24 或 hybrid winner。

## 6. Load、publication delta 与 capacity admission

### 6.1 当前 budget

T47 延续 `tools/t14_load_budget_policy.v2.json`：

```text
datapack_authored_entries  6000 soft / 6600 reference   REPORT_ONLY
eager_publication_rows    18000 soft / 21000 hard
lazy_logical_rows         16000 soft / 56000 hard
lazy_cache_ceiling         1024 soft / 4096 hard
lookup candidates            64 soft / 128 hard
lookup p95 ns           1000000 soft / 2000000 hard
server reload ms           5000 soft / 10000 hard
client reload ms           5000 soft / 10000 hard
```

其余 sync、retained memory、allocation、server/client index hard gates 同 v2 policy。
判定器是 `tools/forward_v2_budget_decision.py`，T47+ 共用：

```text
correctness / pending
  -> non-authored hard ceiling（淘汰）
  -> authored REPORT_ONLY（只报告）
  -> 所有 soft budget（只警告）
  -> predeclared tie-break
```

Authored entries 无论超过 6000 soft 还是 6600 reference hard 都只报告，不参与 winner、
elimination 或 `failed_gates`。其它轴的 soft 超线同样只警告；不得为了让候选存活而抬
soft 数值或 hard gate。T37–T46 历史 builder 保持冻结，不回写这套判定。除 authored 外，
任何 blocking hard gate 不得上调。

全 545 candidate 若全部 lazy，静态 relation 算术为：

```text
opening lazy 2758 + candidate relations 47894 = 50652
hard reference 56000
naive headroom 5348
```

这只是 red-flag / admission 参考，不是 PASS。T46 已证明 integrated closing 不能由
opening + card delta 推导；时间、内存、同步、lookup 与 cache 必须实际测量。

### 6.2 测量顺序

```text
per publication group
  -> T47 card aggregate
  -> integrated T37-T47 current runtime
```

每层对 immediate、on_demand、hybrid 做 correctness 与 load gate。测量覆盖：

```text
logical / eager / lazy / cache
server and dedicated-client reload/index p50/p95
enumeration followed by lookup
lookup hit/reject p50/p95/max candidates and latency
sync bytes
retained memory
allocation bytes
group/shard/router overhead
```

Pending 不得填 0。Card-only PASS 不能替代 integrated PASS；fixture measurement 不能成为
production winner。Winner 必须可由 frozen policy + raw measurements 重算，不使用事后
composite score。

### 6.3 Capacity-bound lock

R0 可以用完整 545-family candidate fixture 做 router/load preflight，但 fixture 不是 production。
Production lock 必须由完整 capability cohorts 与 capacity envelope 共同决定：

1. 先剔除 unresolved、lossy、player-path-open 或错误 owner 的 family；
2. 对剩余完整 semantic cohorts 做 deterministic group/shard dry-run；
3. 在不切开 family 的前提下冻结最大可评审 set；
4. 要求 `N >= 300`；
5. 冻结后重新执行 production card-only + integrated measurement。

若 frozen lock 的正式测量失败，不允许临时减少几条 relations、改变 cache 或抬高 hard gate；
必须保持 BLOCKED 或撤回并按完整 semantic cohort 重签。

### 6.4 Authored accounting

Publication delta 分别记录：

```text
compact family documents
publication policy documents
identity/fluid/form runtime datapack entries
player-path support recipes
worldgen/support datapack entries
other declared support
vanilla datapack entries
```

Closing authored 是 opening 5,706 加实际 delta，不预写成 `5706 + N`。超过 6,000/6,600
只产生 report-only 状态；不得伪装成未计数或据此淘汰 materialization candidate。
