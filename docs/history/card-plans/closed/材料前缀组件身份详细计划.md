## 0. 边界

做：

- 库存前缀收成共享 Item + `prefix_material`（名称落地时定；与 `tool_material` 同形的 `MaterialId` 字符串组件）。
- `MaterialLookup.stack(material, form)` 成为规范构造。
- gate 语义改为「允许的 live `(material, prefix)` 栈」，不再为库存前缀分配 Item id。
- 管/缆/hosted ore 的共享 Block 方向写进后续 child，本卡第一刀只切库存。

不做：

- 哑方块（storage `block`、casing、rock）改 BE。
- 流体 / FluidType 展开。
- 其他模组 `c:` 标签适配层。
- compact family 改 parameterized / 改 Holder 粒度。
- 仓储桶跨前缀单位换算（仍见缺口页 §4）。
- DataFixer / 旧 `cruciblecraft:{material}_{form}` 别名。
- 重开工具头 identity 分母；只收已经折回前缀的那些 `MaterialItem`。

## 1. 为什么现在的 mill 仍贵

`MaterialDefinition.forms()` 已经是 GT6 事实集。live 物品却走
`MaterialCatalog.registeredForms()` ← gate。`ModItems.registerMaterials` 对每个
gate 形态 `new MaterialItem(material, form)`。因此「加材料」= 新 id + 模型 +
标签 + 创造栏枚举，即使配方规则已经按 `(material, prefix)` 写。

已有先例：`MaterialToolItem` + `TOOL_MATERIAL`、`OreMaterialBlockItem` +
`ORE_MATERIAL`、流体单元。库存件还停在烤进 class 的字段上。

## 2. 目标运行时形状

```text
Item   cruciblecraft:dust
Stack  { count, cruciblecraft:prefix_material = "iron" }

MaterialLookup.stack("iron", DUST)
  -> new ItemStack(PREFIX_ITEMS.get(DUST)).set(PREFIX_MATERIAL, "iron")

MaterialUnits.resolve(stack)
  -> Entry(materialId from component, form from PrefixMaterialItem, units from prefix)

Ingredient
  -> DataComponentIngredient.of(false, PREFIX_MATERIAL=iron, PREFIX_ITEMS.get(DUST))
```

`PrefixMaterialItem` 实现 `MaterialFormItem`：`form()` 来自物品，`materialId()` 来自栈组件。
无组件或未知材料走现有 `UnknownMaterialItem` / `MISSING_MATERIAL` 恢复，不要变成空气。

`HotIngotProcessing` 改为：物品是 `ingot_hot` 前缀 Item，熔点从组件上的材料读，不要再
`instanceof MaterialItem` 取烤死的 definition。

外部 `formItems()`（例如原版铁锭）仍是别的 Item；`MaterialUnits` 的 tag 索引继续只收录这些外部条目。

## 3. 落地切片（unique-active）

A+B 一起切：所有库存前缀，不是只切粉尘。禁止 live 双身份
（`cruciblecraft:iron/dust` 和 `cruciblecraft:dust` 同时注册）。

GT mill JSON 仍可写 `cruciblecraft:{material}/{form}`，由
`PrefixMaterialItemCodecs` 在解析时改成前缀 Item + 组件。
`shaped_catalyst` 同样走这套 codec。vanilla cooking 的输出必须是带组件的
ItemStack，不能写成裸 `cruciblecraft:ingot`。

### 切片 C — 管 / 缆（本卡不做，另开 child）

`AbstractPipeBlock` / `CableBlock` 已有 BE 与六面连接 state。材料从
`PipeCatalog.Entry` / `ElectricalConductorCatalog.Entry` 烤在 Block 上，改为 BE 字段。
A+B 关卡不依赖 C；不要把哑方块塞进 C。红石线与原版石头矿保持按材料独立 Block。

## 4. 配方与生成器

`MaterialLookup.ingredient(material, prefix)` 今日返回 tag ingredient。切片 A 起，
CC 自有库存形态必须返回组件配料。`MaterialRuleExpansion.withStringComponents`
已经会走 `DataComponentIngredient`；扩展它而不是再发明一套。

`recipe_bulk` / ordinary-closure 生成器按 `(material, prefix)` 发射 runtime id 的地方，
改为发射前缀 Item id + 组件。**不要**手改几千份 JSON 充数；改生成器再重 seal 所触及的波。
逻辑身份键仍是 `material_form:{material}/{form}`。本卡若只切粉尘，只重 seal 粉尘操作数所在 lock，不得改无关 `complete_family_count`。库存前缀已全部切完，触及的 mill 波按字节漂移 reseal。

统一器：同前缀换材料是改组件，不必再为「铁粉→锻铁粉」各写一行 item→item。
其他模组果汁、缺前缀、流体行仍按现有 blocked 规则，不发明 stand-in。
