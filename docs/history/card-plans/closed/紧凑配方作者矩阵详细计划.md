## 0. 决策

上一张 READY 只证明：独立客户端进得去；family 合同没改。和 GTM 的差
还在 **一个 Holder 里写什么**：

| | GTM | 现在（传输卡之后） | 本卡 |
| --- | --- | --- | --- |
| Holder | 一条小机器配方 | 整个 semantic family | 仍是整个 family |
| 输入 | 优先 tag | exact item id | 仍是 exact |
| 作者正文 | 短配方 | 1116 条几乎相同的 relation | 共享字段 + 字典 + 允许元组 |
| 线上 | 手写 `toNetwork` | family 内字典二进制 | 编 **作者矩阵**，不再先展开再编 |
| 最终关系 | 小配方集合 | exact 1116 | **同一** exact 1116 |

「改配方写法」不是改成 tag 模糊匹配，也不是把 `#0025` 拆成 1116 个
RecipeHolder。那两件事都会动 exact 合同或 T48 分母，上一张已禁止。

本卡打开的是 workflow §4.5 已经预留、运行时一直 fail-closed 的那条：
**大型 expansion 用 template + slots 写，加载后再展开成 exact
relations**。现成 `ParameterizedSpec`（`template` + `Map<String,String>`）
不够表达元组表，不要拿它充数。冻结新的作者矩阵信封。

```text
runtime/compact-recipe-authored-matrix
```

## 1. 完成后应该成立的工作流

```text
freeze authored-matrix schema
  shared duration / EU / action / chance / source_kind / source_recipe
  item / fluid / ingredient dictionaries
  explicit rows: (input, output, fluid, stable_id, evidence, shadow_order)
emit: shared-shape N>=2 families write matrix
      singleton families stay inline exact
MapCodec loads matrix; relations() absent or empty
StreamCodec encodes the matrix (not 1116 expanded rows)
CompactRecipeFamilyProvider expands to the same exact relations
equivalence: stable_id set, fingerprint, input/output signatures
dedicated update_recipes smaller than the current ~4.09 MiB
T48 145 / 34091 / 3532 counts unchanged
rewritten generated JSON -> re-seal hashes only
  -> COMPACT_RECIPE_AUTHORED_MATRIX_READY
       or BLOCKED
```

关键分界：

1. 语义 family 仍是 1 个 `family_id`、1 个 RecipeHolder。
2. 最终 logical relations 必须与关卡前逐条等价。多一条、少一条、
   换成 tag 匹配，都是失败。
3. 展开发生在 `CompactRecipeFamilyProvider.prepare*`，**不是**
   `Recipe` 构造时先摊成 1116 行再同步。否则整包还是 4 MiB。
4. 现有 `parameterized()` 若仍是「任意出现就抛」，必须改成：认识的
   矩阵模板才展开，未知模板继续 fail-closed。
5. 关闭后 `next_unassigned = true`。账本内容下一张仍是 Item Network
   Core，未签发。

## 3. 权威分母

本卡不拥有新 family。分母是 **作者单元** 和 **展开后等价**。

### 3.1 必须改写法的 family

live `type = cruciblecraft:compact_gt_recipe_family`，且：

- 全部 relation 共享同一配方形状（duration / EU / action / chance /
  source_kind / source_recipe 一致，只换物品 / 流体 / stable_id /
  evidence / shadow_order）；
- `N >= 2`。

代表条目仍是 `gt.recipe.bath#0025`（1116 行、1 种形状、147 / 9 / 15）。
39 个 >1 MiB JSON 必须改写。其他 shared-shape 多行 family 一并改，
避免 emit 分叉。

单行 exact、或行间 duration / IO 形状不一致的，保持 inline
`relations[]`。不得为了「全是矩阵」把异形行硬塞进一个模板。

### 3.2 作者信封（`DESIGN_POLICY`）

```text
authored_form = matrix_v1
relations     = absent | []
matrix:
  shared: duration, eut, special_value, can_be_buffered,
          item_input_counts, item_input_actions, output_chances,
          source_kind, selected_source_recipe
  dicts:  items[], fluids[], (optional ingredients[])
  rows:   [input_idx, output_idx, fluid_idx, stable_id,
           evidence_hash, shadow_order]
```

字段名实施时钉，语义不行改。行是 **允许元组**，不是生成器。
`parameterized.template = "compact_matrix_v1"` 或并列字段都可以，
但不能是开放 `Map<String,String>` 冒充 1116 行。

解码 / 展开上限沿用传输卡：

```text
decode_relations_ceiling     = 4096
item / fluid IO per row      = 16
max_recipe_entry_wire_bytes  = 524288
```

未知模板名、行数与 lock `stable_ids` 不一致、字典越界：分配前拒绝。

### 3.3 本卡 `deferred`

- 开放 tag 输入（`ingots/copper` 匹配任意铜锭）
- GTM 一条逻辑配方一个 RecipeHolder
- 传输 §3.2 fragment（单条已经 < 512 KiB）
- 自定义 compact manifest，绕开 `update_recipes`
- 把 tool_head 折进 material prefix

### 3.4 本卡 `out_of_scope`

- Item Network Core、封面网、核电、原版替换余量
- 重开 T48 family 集合或改 `3532` identity catalog
- 提高 `NbtAccounter` / Varint21
- 玩家发行 / RC soak

## 4. 实现约束

- 物品注册政策不动。exact 的是 **展开后的关系集合**。
- `recipe_bulk` emit 是作者源。不要手改几千份 JSON 充数。
- 只读 lock 的 family / stable_id 列表；改的是 generated 正文。
- 被改写波次：重算 generated hash，**重 seal**。不得改
  `complete_family_count` / relation 计数来「看起来更干净」。
- 集成客户端仍复用 server epoch。
- 独立客户端从同步到的 **矩阵** 重建，再在 client loader 展开；
  禁止两边展开结果不一致。
- 不得把「任意 raw pickaxe head + 油」写成模板。
- 不得为了缩小 JSON 丢掉 `stable_id` 或 evidence hash。

## 7. 撤回

实施中发现阻塞时只有三种合法结果：

1. 缩小改写范围到「共享形状且 N 足够大」的 family，写清异形行为何
   仍 inline；
2. 保持 `BLOCKED`，写清缺的是 schema、展开等价还是 dedicated 整包
   证据；
3. 正式撤回并重签，保留旧卡路径。

不得用开放 tag、拆 Holder、或只测集成客户端冒充 READY。
不得把本卡写成 T48 重做或 Item Network Core 已开工。

关闭时：本计划移到 `card-plans/closed/`，补 stage archive 与 work log；
更新 history index、roadmap、workflow、verification、known-issues 与
账本第 0 节；被改写波次只重 seal 哈希；不自动创建 Git commit。
