## 0. 先读这一节

### 0.1 这张卡是什么、不是什么

T29 是 T27 从尚未关闭的 `v1_required` 集派生出的 **最后一张 v1 实现卡**。
它的 identity 只有一个：`multiblock_kinds/crucible`。

完成 T29 的意思是：

> 注册并验证 `cruciblecraft:large_crucible`，形成 3×3×3 开顶多方块，
> 容量 432 锭单位，底层吃 HU、顶层进出料、中间层模具，
> 复用单块坩埚已有的成分罐 / 热模型 / 炼钢控制器，
> 不与 `cruciblecraft:crucible` 抢 id。

完成 T29 **不等于** 1.0 已经可以发货。见第 0.4 节。

## 7. R4 · 结构 JSON

### 模板

复制现有 schema v1 文件的写法，不要发明第二套格式：

```text
src/main/resources/data/cruciblecraft/multiblock_structures/tank_3x3x3.json
src/main/resources/data/cruciblecraft/multiblock_structures/large_boiler.json
```

硬约束（`MultiblockStructureDefinition`）：

- `schema_version: 1`；
- 控制器 palette 必须落在局部 `[0,0,0]`；
- 无重复 offset；
- 扫描体积远小于 4096。

### 几何（局部坐标，控制器在底面中心）

```text
C          [ 0, 0, 0]
8 × energy [±1/0, 0, ±1/0] except origin     palette: energy_input / HU
AIR        [ 0, 1, 0]
8 × mold   [±1/0, 1, ±1/0] except [0,1,0]    palette: 固定墙（无独立 mold port）
AIR        [ 0, 2, 0]
8 × item_fluid [±1/0, 2, ±1/0] except [0,2,0]
```

## 9. R6 · 行为接线

### 控制器每 tick 应做的事

1. 校验结构；失败则拆解，内容留在过程核（与 tank/boiler teardown 先例一致）。
2. 从底层 energy 端口吃 HU，经 `heat_energy_input` 进过程核。
3. 从顶层 item/fluid 端口进食 / 出料；输出堵塞时停，不丢物。
4. 过程核升温、合金、炼钢。
5. 模具槽 `cast()`；输出满则 jam。
6. 可选 SOURCE_DERIVED：底端口 KU + 结构内有氧 → 向核加入 Air。接不上就在 source evidence 里标 DESIGN_POLICY 缺口，禁止假称已实现。
7. 掉电：缓冲耗尽后过程停止，内容保留。
8. 存档：成分、温度、炼钢状态、plugin id、模具槽。

### 明确不要做的事

- 不要让 large crucible 去搜邻接 `CeramicMoldBlock` 来“更像 GT6”；
- 不要把单块也改成 UI 模具；
- 不要在成功形成后把世界空气变成墙。
