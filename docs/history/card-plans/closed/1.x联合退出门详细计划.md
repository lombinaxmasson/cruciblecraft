## 0. 为什么现在是验收，不是再开一张内容卡

项目从「做一个 GT6 坩埚」长成工业主链。中途为了保守，加了很多现在看起来就是
历史债的限制：不全量移植声明、TXX 预估、硬顶、selected-only 机器矩阵。配方长尾
后来证明：没有生成器和分类，前期特例对后期几乎没用；硬顶还挡过导入。

这张卡承认两件同时为真的事：

```text
1.x 已认领的关闭工作 = 有效，必须联合验收
1.x 不是 GT6 终点     = 同样有效，exit 之后要有对照工具才能继续长
```

缺的主要不是「再列一遍 GT6 文件」，而是 **CC 侧有没有可重复的增长机制**。R0
只固定已经看见的对应关系和缺口类型；完整工具和「之后怎么做」留给后继 program。

## 2. 已经看见的结构性缺口（种子，不是普查）

这些是对照代码树后的**已知类型**。R0 把它们写成机器可读行，禁止在本卡里展开
成实现。后继工具按同一 schema 继续补行。

### 2.1 对应关系已经存在（增长机制可用）

| GT6 源概念 | CC 机制 | 备注 |
| --- | --- | --- |
| `gregapi/oredict` 材料/前缀 | `MaterialPrefixCatalog` + 材料 JSON | 前缀是启动 catalog，不是运行时 datapack 增行 |
| `gt.recipe.*` ordinary 行 | compact `exact` / `exact_multi` + 逐波 Python builder | 有导入路径，没有通用「dump → 任意 map」生成器 |
| 已选 MTE 机器档位 | `machine_tiers.json` → `MachineTierCatalog` → `ModMachineVariants` → 自动注册方块 | 显式 catalog 行会注册；不做 kind×材料笛卡尔补全 |
| 矿脉 / 油气 | T20 129 identity + fluid deposits | 不宣称 GT6 全量 worldgen |
| 管 / 缆 / hopper | 独立 runtime + 部分 catalog | 1.x 物流主链 |
| Storage MTE | T44 28/624 catalog | 已收回的排除表子集 |
| Bath / Smelter MTE 可持身份 | 两个 identity catalog | 身份 ≠ 行为生成器 |

### 2.2 看起来有数据、增长仍靠 Java

| 缺口 | 证据 |
| --- | --- |
| 已有 kind 的新档位 | 给 `machine_tiers.json` 加显式行即可注册方块；`registerTieredProcessingBlocks` 遍历 catalog。`automaticKindTierCompletion: false` 只禁止「每种材料都自动出一台」 |
| 新 kind / 信封 | 新机器种类仍要在 `ModProcessingMachines` 写 slot / tank / GUI。档位只叠加 catalog 里的 energy window；离心机高档信封是 Java 特例，不是通用 datapack 信封 |
| 参数化配方 fail-closed | `CompactRecipeFamilyProvider` 遇见 `parameterized()` 直接抛错。长尾只能 compile-time exact |
| 逐波 builder 不可复用 | `build_ordinary_wave.py`、`build_smelter_deferred_recycling.py` 等按卡复制。前期材料规则树不喂后期 compact 导入 |
| 计数硬顶仍在代码里 | `ALL_PUBLISHED_RECIPE_BUDGET = 21000`（已 deprecated，仍被 loader/GameTest 引用）、lazy 56k、cache 4096、shard 128。closeout 已改成 `UNVERIFIED_SCALE`，runtime 口径还没统一 |
| 封面不是 GT6 物流网 | `cover_definitions.json` 只有 filter / shutter / pump / conveyor / retriever / robot_arm / pressure_valve / selector |
| 能源只有 selected 链 | 青铜锅炉 / 蒸汽机 / 发电机 / 燃气 / 燃油。电池、变压器、反应堆没有 catalog 生成器 |
| 排除表仍无 owner | T13c 的 Panels 348、Sensors 21、Portals 19、Batteries 37、Reactors 46 从未进 1.x 分母 |

## 6. 后继：对照工具，不是核能

Exit 通过后，默认下一张 major program 是
`portfolio/source-capability-map`。它才拥有：

1. 把 seed 做成可重复跑的对照工具（GT6 loader/域 → CC 机制或 `none`）；
2. 区分内容缺失和能力缺失（没有生成器 / 硬编码 spec / 计数顶 / 无 owner）；
3. 规划增长顺序：先修机制，再按域导入。候选域包括物流封面网、新 kind 信封
   数据化、参数化配方 runtime、原版替换、非矿世界生成、作物/食物、能源其余层、
   面板/传感器、核能。已有 kind 加显式档位不是缺口；笛卡尔补全也不是目标；
4. 明确核能只是图上的一行，不是自动开工。

本卡不预写那张 program 的 production lock，也不实现工具。

## 8. 撤回

任一 child 发现阻塞时只有三种合法结果：

1. 在本 child 内补齐验收证据；
2. 保持 BLOCKED，先写清缺的是证据还是能力；
3. 正式撤回并重签，保留旧 selection hash。

不得把能力缺口当成 1.x 失败，也不得把 1.x 验收当成 GT6 完成。
