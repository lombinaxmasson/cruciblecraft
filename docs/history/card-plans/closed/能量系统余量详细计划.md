## 目标

玩家看到的「能量机全是占位」要拆开写：电缆和轴是真的；`firebox` 不是
GT6 名；`bronze_boiler` 一类单方块是早期占位，目标形态是和加工机一样的
数据包分档（[`machine_kinds.json`](../../../../src/main/resources/data/cruciblecraft/machine_kinds.json)
+ [`machine_tiers.json`](../../../../src/main/resources/data/cruciblecraft/machine_tiers.json)）。

本卡完成后：固体燃烧室从游戏里消失；现有 `burning_gas_generator` 仍是
生存与邻接 HU GameTest 的邻居热源。它是 GT6 **燃气燃烧室**（Burning Box
Gas，`1602`，出 HU），不是 EU 发电机。本卡不改注册名、不改邻接测试为
`insert`、不删这块占位。后继顺序钉死为 **先加档位再换机器**。

## `converter_catalog_policy`

后继要把锅炉 / 蒸汽机 / 发电机 / 电机 / 燃烧室做成与加工机相同的数据包
分档：kind + 材质档 + 共用 runtime，对照钉住的
`gt6_code/gregtech6` `Loader_MultiTileEntities`。禁止再注册一个
`cruciblecraft:steel_boiler` 这种手写单方块充数。不得把现行
`energy_converters.json` 剩下的 COMPLETE 行当成最终目录。
`burning_gas_generator` 本卡留下当邻接 HU 邻居与生存热源；分档卡按
固体 / 液体 / 气体 / 流化 + 致密变体做成 kind × 材质后，再把测试和生存
换到真燃气燃烧室，最后才删这块占位。邻接 HU 测试不改 `insert`
（蒸馏 / 烘干 / 冶炼 / 焙烧是 `EnergyMode.ADJACENT`，只从下方邻居抽 HU）。

蒸汽机固定 12 KU/t 仍是 `DESIGN_POLICY_FIXED_OUTPUT` +
`DEFERRED_REPLACEMENT`（GT6 6–24 KU/t）。另开动力学卡才能换。

## `battery_policy`（SOURCE_BACKED）

Batteries 是 `MultiTileEntityBatteryEU*` / `AdvEU*` / `LU*`，loader
`14000–14044`、`14500–14515`。不是聚变 `14600`/`14601`、不是处理器晶体、
不是 Logistics Core 的 256–1024 EU、不是 `electric_motor`。

## `transformer_policy`

电变压器是电压台阶。CC `rotational_gearbox` 不是 GT6
`MultiTileEntityTransformerRotation`。不得用齿轮箱冒充变压器。

## 本卡做什么 / 不做什么

做：

1. 签发本余量表为 unique active。
2. 删除 `firebox`、`bellows`、独立焦炭物品；焦炉与相关配方改
   `coal_coke/gem`。
3. GameTest 邻接 HU 继续用现有 `burning_gas_generator` 当下方邻居（可
   seed HU 缓冲），不发明测试用火箱，也不把邻接测试改成 `insert`。
   钛档 HU 窗口大于占位 24 HU/t 的那条已走 `insert`，不再扩到青铜邻接。
4. 人读账本与玩家指南去掉火箱首小时路径；占位方块按燃烧室称呼，不叫发电机。

不做：

- 不实现分档燃烧室 / 锅炉 / 蒸汽机 / 发电机 / 电机。
- 不删 `bronze_boiler` 等占位机。
- 不改 sealed R0 JSON、`growth_order.json`、`capability_map.json`、
  `census_excluded_object_reclaim.json`。对照图里仍写着
  `bronze_firebox` 的 selected 行当历史 1.x 子集。
- 不预写后继 topology child。
- 不创建 Git commit（除非用户另行要求）。

## 诚实玩法缺口

删火箱后，固体燃料 → HU 暂时没有。首小时蒸汽链（火箱→锅炉→蒸汽机）断掉。

`burning_gas_generator` 的燃气燃烧室占位。
