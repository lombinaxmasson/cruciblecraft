## 2. 数据权威与编译器分层

后续波次必须能复用同一条流水线。T45 把下面五层分开，禁止把其中两层合并成“一张 JSON
既是 lock 又是 shard”：

```text
Source Pack     来源与 revision；决定 provenance，不决定运行时切片
Card            work-set / lock / census / gap 的人工评审单位
semantic family 一个 ordinary recipe family 的全部 logical relations
Publication Group  (target_map, publication_group) 的 materialization / load 单位
Shard           query 可直接求出的 lookup/cache 单位
```

V1 **一个 semantic family 对应一个 authored document**。编译器在构建期把模板调用展开为
[`CompactGTRecipeFamilyDefinition.Relation`](../../../../src/main/java/com/masson/cruciblecraft/recipe/gt/CompactGTRecipeFamilyDefinition.java)
可直接解码的精确 records。运行时继续走现有 compact codec / provider / loader。

流水线：

```text
pinned raw source
  -> normalized Source Pack
  -> catalog / candidate diagnostics
  -> immutable production lock
  -> bulk IR
  -> operand resolution
  -> finite template expansion
  -> exact CompactGTRecipeFamilyDefinition.Relation records
  -> generated root
  -> publication-group + shard manifests
  -> Java codec / runtime / GameTest / load
  -> census / readiness
```

`analyze` 模式只读，可对整个 3,076 gap 按 resolver/template 缺口聚类。只有引用已签发
production lock 的 `compile` 模式能写出闭卡资源。编译器不得自行挑选或替换 family。

## 4. R1：OperandResolver、IR 与有限模板

### 4.1 Resolver 链

确定性、可复现，禁止按显示名或“看起来像方块”猜测：

```text
1. exact vanilla / CC runtime ID
2. explicit source object/meta mapping
3. registered material / form
4. proven canonical tag
5. proven source-derived alias
6. explicit component / object expression
7. otherwise unresolved
```

每个结果输出 mapping class、evidence、registration authority、route key 和 disposition。
下列情况阻断**整个 family**，禁止部分扣 gap：

- unresolved 或损失性映射；
- 基数与 source relation 不符；
- shadow order 冲突；
- 注册成功但玩家不可取得；
- Bath MTE / 浴液参数被误判成普通 block。

T45 首先实现 block-object resolver，消费 T43/T44 已冻结的现代 runtime identity。需要新增
的 Block / BlockItem 必须有 source identity、state/model/loot 和生存取得边；禁止注册同名
无方块行为 item 或无来源 crafting token。

### 4.2 IR 与 V1 模板

IR 至少保留：semantic family、source row、stable relation、shadow order、item/fluid
operands、consume/preserve/wear、chance、duration、EU/t、special、buffering 与逐字段
provenance。

V1 只允许：

```text
exact_singleton
exact_relation_set
explicit finite_bindings
keyed_join with cardinality proof
```

禁止隐式笛卡尔积。T45 首轮 overlay 全是 1-relation family，预期走 `exact_singleton`；若
R0 发现某 family 不是 singleton，只能在其全部 relations 完成后扣 family gap。

`t45_recipe_compile_spec.json` 只引用 lock 内 family。compile report 必须预测 T14
authored-entry 天花板：当前 integrated opening 为 4,484 / 6,600；即便 397 个新 authored
document 全过，仍应显著低于硬上限。跨 family authored bundling 是 V2，不进本卡。

用 T43 的 407-family corpus 做 **test-only** semantic replay：证明新编译器对历史 stone
语义的输出与 T43 生成根一致，但绝不重写 T43 文件、policy 或收据。
