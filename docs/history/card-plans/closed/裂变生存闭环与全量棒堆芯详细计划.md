## 0. 开场判断

46 个棒身份不等于 46 套独立 Java 行为，但也不等于一个棒换名字：

```text
EMPTY       1
ABSORBER    1
REFLECTOR   1
MODERATOR   1
NUCLEAR    17
DEPLETED   17
BREEDER     4
PRODUCT     4
total      46
```

- 17 个 `NUCLEAR` 共用燃料棒算法，但 durability、`neutron_self`、
  `neutron_other`、`neutron_div`、`neutron_max` 和 depleted target 不同；
- 4 个 `BREEDER` 共用吸收/嬗变算法，但 durability、neutron loss 和 product
  target 不同；
- absorber、reflector、moderator 分别吸收、反射和调制中子；
- depleted / product 是不同回收输入，不能因堆芯内大多被动而合并身份。

因此本卡采用“一次实现共享行为、逐条验证参数与转化”的策略，不为每种棒复制
host，也不把不同材料输入输出塞进 alternatives。

当前已有：

- `nuclear_reactor_rods.json` 的 46 个身份及 `ReactorRodCatalog`；
- `ReactorRodPhysics`、耐久/嬗变、1×1/2×2 堆芯、邻接中子、启停与存档；
- 蒸馏水 → 蒸汽；
- GT6 来源贴图与 5 个 `cruciblecraft_nuclear_fission` GameTest。

当前硬缺口（2026-09-07 核对，详见第 7–9 节）：

- 无 Canner host / `ModRecipeMaps.CANNER` / EMI / LV 合成；
- 48 条核内容关系均未发布（空棒挤压可立即写，其余依赖 in-card 组件）；
- `OD_CIRCUITS[1]` / `[5]` 不存在；活目录只有纸质 `programmed_circuit`，不得折 tier；
- `IL.MOTORS[1]` / `[4]`、`IL.PISTONS[4]` 不存在；`compact_electric_pump_lv` 身份已有，但配方是 closed 物流卡的 vanilla / shapeless stand-in；
- `OP.casingMachineDense(Pb)` 不存在，不得用 `machine_casing_double` 顶；
- Press 运行时 `itemInputs=2`，电路零件需要 3 输入（GT6 GUI 已是 3）；
- Laser Engraver 是 LU 能量桩，未接 `RM.LaserEngraver`；机器合成仍被 `LuPrerequisiteGameTests` 断言为空；
- `zirconium/scrap` 与多数核材料 `dust_div72` 未进 materials 门；
- `NuclearFissionGameTests.fortySixRodsAreRegistered` 仍断言堆芯/棒配方必须 blocked；
- `nuclear_started = false`，capability 目录尚未创建。

## 4. 实施阶段

第 8–10 节已锁定来源行、递归图和 host 选型。实施时先把第 8 节写成
`tools/waves/runtime/fission-survival/source_matrix.json`，再发配方。
代码真正开始时才把 `unique_active_wave` 设为 `runtime/fission-survival`。

### A. D0 全量来源与前置件矩阵

在发布任何配方前生成 48 行 source matrix，每行至少包含：

```text
source location / source id
input material + prefix + amount
machine / shaped pattern
consume | preserve | wear
item outputs / fluid outputs
CC registry translation
ingredient recursive acquisition
status = ready | requires_in_card_component | blocked
```

硬核对：

- `OP.wireGt01` 只能落到对应材料的 CC `wire`，不能落到任意导线；
- `ANY.Cu` 只能落到铜家族；
- `MT.Os` 等材料必须保持同材料；
- `OD_CIRCUITS[tier]` 不能折成单个无 tier 的 `programmed_circuit`；
- `IL.PISTONS[4]` / `IL.PUMPS[1]` 必须是对应 compact component identity；
- 缺 prefix / material / component 时该行保持 blocked，不生成 recipe JSON。

本阶段必须给出 T1/T5 circuit、T1 pump、T4 piston 的递归获取图。若真实获取
依赖尚未实现的 Laser Engraver、motor、plate/gear/wire 形态或 closed-card
stand-in，记录准确 owner；不得把 endpoint item 存在误报为玩家闭包。

若 48 行中有 blocked，本卡继续保持 active/BLOCKED；不得把范围静默缩回
“只发布 U-238”后关闭。

### B. Canner host（已锁定）

Mixer（6/1/6/2）和 Assembler（无流体输出）都不能无损表达 GT6 Canner。
新增独立 host，不复用 Mixer/Assembler，也不用 `machineCrafting()` 铜炉占位：

```text
ModRecipeMaps.CANNER
ModProcessingMachines.CANNER = chemicalSpec(
    "canner", 2, 1, 0, 1, 128000, 128000, 2, 1, 0, 1, EnergyType.ELECTRIC)
```

- `machine_kinds.json`：`cruciblecraft:canner`，`acquisition_template: machine_generic`
- `machine_tiers.json`：只注册 LV，`sourceId` 20161，材质 `steel_galvanized`，
  `energy: ELECTRIC`，`inputMinimum/Nominal/Maximum` 16/32/64，罐容 128000
- 不注册 T2–T5 Canner
- `chemicalAllowsPreserveCatalyst` 对 canner 保持 false（两格都 CONSUME）
- 氚卸出是 1 物入 / 1 物出 / 1 流体出，落在 2/1/0/1 内
- 装棒配方全部 `eut=16`、`duration=16`
- 通用化学面合同是正面出物、其余进物、能量背面。GT6 Canner 更细
  （左入/右出、顶流体入/底流体出、能量 BACK）。若通用合同无法表达氚卸出
  与双槽装棒，再做 typed specialization；不得把双槽压成工作台配方

### C. 全量棒生命周期

用 catalog 驱动，不写 46 份手工分支。稳定 recipe id 建议
`recipe/nuclear/<rod_id>.json` 或 `recipe/machine/canner/<rod_id>.json`，
与棒 `source_id` 一一对应：

1. 空锆棒：1 锭 Zr + cell extruder shape，96 EU/t，64 t，模具 PRESERVE；
2. utility：3 条 stick + empty rod，Canner 16/16；
3. fuel：17 条 material stick + empty rod，Canner 16/16；
4. breeder：4 条 material bolt ×4 + empty rod，Canner 16/16；
5. depleted：17 个 fuel target 与 17 条 centrifuge 64/256 精确对应；
6. product：4 个 breeder target；3 条 centrifuge（9441 为 512/256）+ 1 条 tritium Canner unload。

每条 relation 的稳定 ID、EMI identity、输入动作、时间、EU/t、输出数量和材料
都必须逐项校验。不同输入/输出不能用 alternatives 聚成虚假的笛卡尔积。

### D. 两个堆芯

- 1×1 与 2×2 使用 source pattern，不自行发明几何；
- CC `shaped_catalyst` 固定 3×3。GT6 1×1 是 2×2 `"CP","wM"`，垫空到
  `"CP " / "wM " / "   "`，空格保持空，不改相对位置；
- 2×2 已是 3×3 `"PCP","CMC","PCP"`，无工具字符；
- `lead/machine_casing_dense`、`circuit_master`、`compact_electric_piston_ev`
  逐格等价；
- 1×1 单槽与 2×2 四槽分别验收，不把 2×2 当四个独立 1×1；
- 插入棒自动停机、允许的拔棒 mode、邻接堆芯方向和 NBT 存档保持；
- 17 个 fuel 和 4 个 breeder 的 target 转化必须替换为 catalog 指定 identity。

### E. 玩家纵向闭环

最低闭环：

```text
真实前置件
  -> LV Canner + 2×2 Reactor Core
  -> Extruder 制空锆棒
  -> Canner 制 U-238 fuel rod
  -> 插棒、加蒸馏水、启动
  -> steam
  -> 现有 steam consumer
  -> depleted U-238 rod
  -> Centrifuge 回收
```

另做一条 breeder → product → recovery 闭环，覆盖 centrifuge 和 tritium
Canner unload 两种终点。创造栏直接取物只能用于单元行为测试，不能作为玩家闭环证据。
