## 0. 决策

非矿世界生成 R0 已关闭为 `NON_ORE_WORLDGEN_R0_READY`。Trees / Dungeons /
Planets / Center 均为 `requires_new_runtime`，`allows_implementation_child
= false`。下一张不得签树 / 地牢 / 星球 / center 实现，也不得把其余 172
条 dump 特征或 `WorldgenOresVanilla` 写成下一张。不得签物流 core、T13c
implementation child、count-ceiling、combinatorial 或核能。crops / food /
bees 需要新 RecipeMap，且撞上仍为 report-only 的 kind envelope，仍另卡。

继续 growth-order 第四轨 `portfolio/large-content-branches` 的第二个命名
义务。整轨仍不是一张卡。先签最小可审查切片：

```text
portfolio/vanilla-replace-r0
```

它只回答：capability map 点名的两类 vanilla replace loader（Vanilla 添加
vs Replace + ASM）能否由**已有** CC datapack / 导入器 / 配方删除条件作
有界扩展承载，还是必须另开 runtime。R0 READY 不等于原版配方已替换，也不
等于把 T30 121 条 hopper vanilla 配方重开，更不在 topology 预分配实现
child。

## 1. 完成后应该成立的工作流

```text
pinned capability-map vanilla replace rows (2)
  + t13 tree blobs for 3 source files
  -> inherited_denominator.json
  -> source_semantics.json
       Vanilla loader adds GT6 vanilla-adjacent recipes
       Replace removes / substitutes vanilla recipes
       ASM Replacements is bytecode, not a recipe JSON
       dump mc.recipe.furnace recipeCount=0 is not a census
  -> existing_mechanism.json
       CC datapack recipes are additive (cruciblecraft namespace)
       a few minecraft:smelting mold-firing recipes are not GT6 replace
       T30 121 hopper vanilla recipes already closed, not this owner
       generic Source Pack importer does not remove minecraft recipes
       no data/minecraft/recipe overrides
       no ASM
  -> replace_contract.json
       what a later implementation card must answer
       what R0 must not invent
  -> feasibility.json
       per category:
         bounded_extension
         | requires_new_runtime
         | defer_to_portfolio
         | blocked
  -> VANILLA_REPLACE_R0_READY
       or BLOCKED / DEFERRED with missing evidence named
```

关键分界：

1. R0 不写 Java、不写 `data/minecraft/recipe/**`、不注册 NeoForge recipe
   removal、不引入 ASM、不跑 GameTest、不签 production lock、不写
   `src/recipe_generated/**`。
2. 分母是 capability map 两行 + 三份 pinned GT6 源文件，不是 dump 配方数。
   `mc.recipe.furnace` / `furnacefuel` / `autocrafting` 的 `recipeCount = 0`，
   不得手填一张假 census。
3. T30 hopper 的 121 条 vanilla 配方已关闭，本卡不拥有、不重开。
4. `WorldgenOresVanilla` 24 条属于非矿 worldgen remainder 172，不是
   loader 替换。
5. 只有某类对照到**具名现有** CC 配方管线且判定 `bounded_extension`，才
   允许**另签**该类 implementation child；本卡 topology 的后继保持未分配。
6. capability map / sealed growth-order / T13 tree / 已关闭 worldgen 与
   T13c / logistics seal 在 R0 只读，不得手改 `cc_mechanism`。

## 4. 现有机制适配面

R0 必须把每个 category 对照到现行 CC 机制或明确写成 `none`：

| 机制 | 现行路径 | R0 用法 |
| --- | --- | --- |
| Additive datapack recipes | `data/cruciblecraft/recipe/**` | 只加 CC 配方；不是 minecraft 配方删除 |
| Mold firing smelting | 少数 `minecraft:smelting` | CC 模具烧制；不是 GT6 vanilla replace |
| T30 hopper vanilla | 121 条已关闭 hopper 配方 | 已关闭；不是本卡分母 |
| Generic importer | `GENERIC_RECIPE_IMPORT_READY` | 现有 host 接 Source Pack；不删除原版配方 |
| `data/minecraft/recipe` | 不存在 override 树 | 不是已有替换面 |
| ASM | 无 | 1.21 NeoForge 不能假装已有 GT6 transformer |

`existing_mechanism.json` 必须写明：缺口是机制，不是漏登记的 hopper 或
模具烧制配方。不得把 T30 121 或导入器 READY 写成已经覆盖 Vanilla /
Replace。

## 5. 替换契约与可行性

`replace_contract.json` 只冻结后续实现卡必须回答的问题，不实现它：

```text
disposition_policy     per-category implemented | planned | deferred | out_of_scope
add_vs_remove          Vanilla loader 添加 vs Replace 删除 / 替换
asm_vs_datapack        Replacements bytecode vs NeoForge recipe conditions
player_acquisition     生存里原版工作台 / 熔炉配方是否仍在
minecraft_namespace    是否允许 data/minecraft 覆盖
load                   配方删除与替换分轴测量
fail_closed            未知 vanilla recipe 不得 silent no-op
```

`feasibility.json` **按类别**取值：

```text
bounded_extension     该类可由具名现有 CC 配方管线有界扩展承载
requires_new_runtime  必须另开 runtime（ASM、全局配方删除、原版覆盖政策）
defer_to_portfolio    合法去向是另一个已命名 portfolio（本切片预期不用）
blocked               缺 dump、缺 schema、或缺测量计划，不能对该类给出结论
```

只有 `bounded_extension` 才允许另签该类 implementation child。
`requires_new_runtime`、`defer_to_portfolio` 或 `blocked` 不得在本卡
topology 预分配实现后继。R0 卡本身仍可 `VANILLA_REPLACE_R0_READY`：
那只证明分母和逐类 verdict current，不等于实现 READY。

预期（预读，实施时必须用证据重放，不得手填）：两类目前都是
`cc_mechanism = none`。Replace 因捆绑 ASM `Replacements`，很大概率
`requires_new_runtime`。Vanilla loader 即使看起来像「再加一批配方」，
只要缺口是原版配方删除 / 替换政策而不是又一个 Source Pack，仍应
`requires_new_runtime`。不得把空的 `mc.recipe.furnace` dump 写成
`blocked` 的唯一理由；权威是源文件 blob，不是空 map。

## 8. 撤回

实施中发现阻塞时只有三种合法结果：

1. 在本卡内补齐验收证据；
2. 保持 `BLOCKED`，写清缺的是源文件、schema 还是测量计划；
3. 正式撤回并重签，保留旧 denominator hash。

不得用「先写一点 minecraft 配方覆盖再补契约」绕过 R0。不得把两类
loader 对照写成 GT6 原版替换完成，也不得把 T30 121 或模具 `smelting`
写成已经覆盖 `Loader_Recipes_Vanilla` / `Replace` / ASM。不得把空的
furnace dump 当成已经数清的配方分母。

关闭时：本计划移到 `card-plans/closed/`，补 stage archive 与 work log
收口；更新 history index、roadmap、workflow 与 verification；不重写已
sealed 的 growth-order JSON；不自动创建 Git commit。
