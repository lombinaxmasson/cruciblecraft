## 3. 对照工具要长什么样

### 3.1 一行一源概念，不是一篇散文

沿用 exit seed 的字段，禁止另起一套词表。R0 冻结这 7 个字段和封闭枚举：

```text
gt6_domain
gt6_anchor
cc_mechanism
correspondence_class    # equivalent | selected_subset | identity_only
                        # | capability_missing | post_1x | out_of_scope_historical
growth_blocker          # none | no_generator | hardcoded_spec | count_ceiling
                        # | no_owner | fail_closed_runtime | selected_only
1x_disposition          # in_1x_closed | in_1x_selected | not_in_1x
recheck_condition
```

`gt6_domain` 至少允许 seed 已用过的值：`oredict` / `loader` / `tileentity` /
`worldgen` / `cover`。inventory 若要加新 domain 标签，必须先在 schema 的
`allowed_gt6_domains` 里登记，不得临时发明。

工具必须能对着 pinned revision 重跑，输出同一 schema 的 JSON。人工表可以当
注释，不能当权威。

### 3.2 分类纪律

```text
capability_missing        ≠ 1.x 失败
out_of_scope_historical   ≠ 永远不许做
selected_only             ≠ 没有数据包档位
already-kind 显式档位行   ≠ no_generator
笛卡尔补全                ≠ 目标
```

矿辞对照前缀那种写法是范本：写「源概念 → CC 机制」，不要写「缺 5,104 行
gregapi」。

### 3.3 最小覆盖（inventory 必须超过 seed）

R0 只证明 schema 和继承。inventory 至少把下列域从「一行 stub」展开到
**可指向源文件/符号的多行**：

| 域 | 展开到什么程度 |
| --- | --- |
| oredict / 材料前缀 | 已有 equivalent；写清启动 catalog 边界 |
| ordinary RecipeMap / builders | 32 个 CC map 对 GT6 dump maps 的有/无 |
| 已有 kind 档位 | 显式 catalog 行 = 能数据包加；不是缺口 |
| 新 kind / 信封 | `ModProcessingMachines` Java spec |
| 封面 / 物流网 | 8 个已有 cover vs GT6 logistics/controller/redstone/detector |
| 能源其余层 | 已选转换链 vs batteries / transformers / reactors |
| 世界生成 | T20 129 + 油气 + 石子 vs 树 / 地牢 / 星球 / center |
| 原版替换 | `Loader_Recipes_Vanilla` / `Replace` → `none` |
| 作物 / 食物 / 蜜蜂 | `none` |
| 建筑方块 | identity-only vs 行为 |
| T13c 排除表 | Panels / Sensors / Portals / Batteries / Reactors |
| census leftover | 4 combinatorial `later:*` + 7 `post_1x:nuclear` + 28 recycling scope |
| count ceiling | 仍引用 21000 / 56k / 4096 / 128 的代码点 |

禁止在 inventory 里实现其中任何一项。也禁止把 GT6 dump 扫成「缺 N 行」的
全量普查；对照是机制账本，不是 recipe census。

## 9. 撤回

任一 child 发现阻塞时只有三种合法结果：

1. 在本 child 内补齐验收证据；
2. 保持 BLOCKED，先写清缺的是证据、dump 还是 schema；
3. 正式撤回并重签，保留旧 selection hash。

不得用「先做一点内容再对照」绕过 inventory。不得把能力缺口写成 1.x 失败，
也不得把 1.x 验收写成 GT6 完成。
