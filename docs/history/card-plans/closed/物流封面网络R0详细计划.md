## 5. 网络契约与可行性

`network_contract.json` 只冻结后续 runtime 必须回答的问题，不实现它：

```text
identity        封面如何加入 / 离开一个物流身份
routing         transfer 的方向变体如何寻址非相邻端点
storage_policy  storage kind 如何声明可被网查询的库存
dump_policy     dump 与 transfer/storage 的语义差
save_sync       网络与封面配置如何进存档
load            玩家获取、网络/存档、服务器行为必须分轴测量
fail_closed     未知 kind / 未知方向不得 silent no-op
```

`feasibility.json` 只能取一个值：

```text
bounded_extension     7-kind 可由 T19 栈有界扩展承载
requires_new_runtime  必须另开网络运行时，不能假装是又一批 adjacent cover
blocked               缺 dump、缺 schema 或缺测量计划，不能 READY
```

`bounded_extension` 才允许另签 core。`requires_new_runtime` 或 `blocked`
必须保持 `DEFERRED` / `BLOCKED`，不得把 Java 草稿写成 READY。

T13 / T27 已写的 `replacement_condition` 对本卡仍然有效：未来实现卡必须
分开证明玩家获取、网络/存档和服务器行为，不能共用机器或能源 owner。
