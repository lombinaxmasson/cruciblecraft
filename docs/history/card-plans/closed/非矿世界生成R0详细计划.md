## 0. 决策

T13c 排除表收回 R0 已关闭为 `T13C_EXCLUSION_RECLAIM_R0_READY`。
`portfolio/existing-mechanism-bounded-domains` 的两个命名义务都已做完
R0 判定：物流封面网 `requires_new_runtime` / `allows_core_child = false`；
T13c 四类 `requires_new_runtime`，Reactors `defer_to_portfolio` →
`portfolio/nuclear`。下一张不得签物流 core、T13c implementation child、
剩余 634/1,230 exclusion 实现，也不得按 sealed growth-order 的第二轨机械
签发 `portfolio/count-ceiling-kind-envelope`。也不把
`post_generator/combinatorial-family-intake` 提前：四条 combinatorial 仍缺
family-atomic 枚举、玩家路径、执行信封和 load 证据。核能 Track C 保持
`started = false`，不得因为 Reactors 已 defer 就开工。

进入 growth-order 第四轨 `portfolio/large-content-branches`，但整轨
（vanilla replace + 非矿 worldgen + crops / food / bees）不是一张卡。
vanilla replace 是 ASM / loader 配方替换，不是 worldgen catalog。
crops / food / bees 需要新 RecipeMap，且撞上仍为 report-only 的
count-ceiling / kind envelope。先签最小可审查切片：

```text
portfolio/non-ore-worldgen-r0
```

它只回答：capability map 点名的四类非矿 dump 特征（Trees / Dungeons /
Planets / Center，预读 **18** 条）能否由**已有** T20 worldgen catalog +
configured/placed feature 管线作有界扩展承载，还是必须另开 runtime，或被
现行 overworld-only 维度政策挡住。R0 READY 不等于树 / 地牢 / 星球完成，
也不等于 190 条 `other_features.json` 全收，更不在 topology 预分配实现
child。

## 1. 完成后应该成立的工作流

```text
pinned dump other_features.json (190 total, slice 18)
  -> inherited_denominator.json
  -> source_semantics.json
       tree placement vs wood / sapling identity
       dungeon as structure, not scatter
       planet rocks vs T20 overworld-only policy
       center biomes / streets / nexus / beacon / testing
  -> existing_mechanism.json

       fluid_deposits.json (2 selected; dump springs remain larger)
       surface_scatter.json (WorldgenRocks selected)
       T33 / T45 / T48 item scatter (already closed, not owners here)
       configured_feature / placed_feature JSON pipeline
  -> worldgen_contract.json
       what a later implementation card must answer
       what R0 must not invent
  -> feasibility.json
       per category:
         bounded_extension
         | requires_new_runtime
         | defer_to_portfolio
         | blocked
  -> NON_ORE_WORLDGEN_R0_READY
       or BLOCKED / DEFERRED with missing evidence named
```

关键分界：

1. R0 不写 Java、不改 `worldgen_catalog/**`、不新增 configured/placed
   feature、不跑 GameTest、不签 production lock、不写
   `src/recipe_generated/**`。
2. `other_features.json` 全表 190 只读继承上下文；本卡只切四类 18 条。
3. Trees 必须按 `WorldgenTree*` 切 9 条具名特征；不得把 `WorldgenStreets`
   因子串 `Tree` 算进 Trees，也不得把 9 个 tree 类写成 9 种木材配方。
4. Planets 只含 capability map 点名的 `planet.rocks` / `moon.rocks` /
   `mars.rocks`。Aether / Erebus / Alfheim rocks 不在本切片。
5. 只有某类对照到**具名现有** CC worldgen 管线且判定 `bounded_extension`，
   才允许**另签**该类 implementation child；本卡 topology 的后继保持未分配。
6. 现行 T20 `DESIGN_POLICY_OVERWORLD_ACCESS` 只读；R0 不得把 moon / mars
   写成已经在主世界 catalog 里，也不得把 `nuclear_started` 写成 `true`。
7. capability map / sealed growth-order / T20 policy / 已关闭 logistics 与
   T13c seal 在 R0 只读，不得手改 `cc_mechanism` 或 `recheck_condition`。

## 5. 世界生成契约与可行性

`worldgen_contract.json` 只冻结后续实现卡必须回答的问题，不实现它：

```text
disposition_policy   per-category implemented | planned | deferred | out_of_scope
player_acquisition   生存里如何遇到橡胶树 / 地牢 / 星球岩石
feature_vs_structure 放置特征、结构、维度谁来承载
tree_identities      9 个 tree 特征 vs 木材 / 树苗 / 树叶 identity
dungeon_semantics    大型 overworld dungeon，不是 scatter 或矿脉
planet_semantics     moon / mars / planet vs 主世界-only 政策
center_semantics     biomes / streets / nexus / beacon / testing
load                 区块生成 / 结构 / 维度分轴测量
fail_closed          未知 feature 不得 silent no-op
```

`feasibility.json` **按类别**取值：

```text
bounded_extension     该类可由具名现有 CC worldgen 管线有界扩展承载
requires_new_runtime  必须另开 runtime（树生长、结构、维度、生物群系）
defer_to_portfolio    合法去向是另一个已命名 portfolio（本切片预期不用）
blocked               缺 dump、缺 schema、或缺测量计划，不能对该类给出结论
```

只有 `bounded_extension` 才允许另签该类 implementation child。
`requires_new_runtime`、`defer_to_portfolio` 或 `blocked` 不得在本卡
topology 预分配实现后继。R0 卡本身仍可 `NON_ORE_WORLDGEN_R0_READY`：
那只证明分母和逐类 verdict current，不等于实现 READY。

预期（预读，实施时必须用证据重放，不得手填）：四类目前都是
`cc_mechanism = none`。Dungeons / Planets / Center 很大概率
`requires_new_runtime`（结构、维度、自定义生物群系）。Planets 还必须对照
T20 overworld-only 政策，不得假装已在主世界 catalog。Trees 可能接近
placed-feature 扩展，但若缺口是木材 identity / 自定义生长而不是又一行
scatter JSON，仍应 `requires_new_runtime`。

## 8. 撤回

实施中发现阻塞时只有三种合法结果：

1. 在本卡内补齐验收证据；
2. 保持 `BLOCKED`，写清缺的是 dump、schema 还是测量计划；
3. 正式撤回并重签，保留旧 denominator hash。

不得用「先写一点 tree feature JSON 再补契约」绕过 R0。不得把 18/190
对照写成 GT6 世界生成完成，也不得把 T20 已选矿脉 / 流体矿 / 石子写成
已经覆盖 Trees / Dungeons / Planets / Center。不得把 moon / mars 写进
现行 overworld catalog 冒充 bounded_extension。

关闭时：本计划移到 `card-plans/closed/`，补 stage archive 与 work log
收口；更新 history index、roadmap、workflow 与 verification；不重写已
sealed 的 growth-order JSON；不自动创建 Git commit。
