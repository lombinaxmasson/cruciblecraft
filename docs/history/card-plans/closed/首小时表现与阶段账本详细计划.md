## 0. 决策

作物食物蜜蜂 R0 已关闭。默认下一张若要「进游戏」，应开 runtime / 内容卡，
不再盖一张冻结收据。当前生存主链已经闭合；对照图之后的缺口是未实现，
不是未冻结。

第一张实现卡不从物流网、作物或核电开工。玩家指南节点 1 的研钵 / 筛分 /
熔炼 / 洗矿仍共用 `block/metal_surface`。T34 已经处理了砧、坩埚、火箱、
青铜锅炉 / 蒸汽机等 19 个目标；那批 sealed，本卡不重开。

坩埚保持 T34 小锅。本卡改掉这个错绑。

同时要把「阶段」写进现行文档：冻结、runtime、玩家完成是三套状态；后续
顺序按可玩垂直切片排；核电按体积是小目录，不再写成自动后期禁区。

物流闭环（发展计划 1.2）本卡不验收。管道 + cover + mass storage 已有
runtime，由人之后自己测。


`bronze_crusher` 已有 `textures/block/machine/bronze_crusher/**`，不在

`particle` 指到 `block/metal_surface`。允许声明的共享族（例如同一机器
的 overlay / particle 同源），不允许四台机器继续共用一张通用底纹当
唯一材质。`smelter` 不得再与坩埚共用 `MultiTileEntitySmeltery` 小锅网格。
不测美丑，不测像素回归。

`overlay_active` 一并迁入。`ProcessingMachineBlock` 没有 `LIT`，本卡不接
工作态；记下以后用 blockstate / BER。工具机动态（杵头材料色、筛上粉尘、
浴槽液面）同样不接 runtime。

### 3.2 阶段账本

实施时必须把下列事实写进现行文档，不得只留在本计划：

**状态词（三套，互不替代）**

| 状态 | 含义 | 现例 |
| --- | --- | --- |
| `frozen` | 分母、来源、可行性已冻 | 各 `*_R0_READY` |
| `runtime_ready` | `src/main` 机制可运行，内容可尚未导入 | 本卡不声称任何冻结项到达此态 |
| `player_complete` | 生存可获得、可运行、可存档，且有 production lock / census（若需要） | 从账本第 1 节删除或改成「已由 `<slug>` 实现」 |

`*_READY` 机制卡只证明 `frozen`。

**后续顺序（可玩垂直切片；同一时刻一张内容卡）**

```text
本卡
  -> 原版替换 MVP（datapack / NeoForge，不搬 ASM）
  -> Item Network Core
  -> Fluid / Generic Network
  -> Batteries
  -> 核电裂变（堆芯 1x1/2x2 + 棒目录 + 7 条离心；见下）

  -> Crops / Squeezer
```

1.2 物流邻接闭环不出现在这张顺序里，由人手工测，不占 `unique_active_wave`。

**核电体积（写进账本，纠正「大后期」读法）**

| 项 | 分母 | 读法 |
| --- | --- | --- |
| T13c Reactors | 46 | 八类棒，不是 46 台堆 |

已实现。
