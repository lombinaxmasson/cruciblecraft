## 1. 决策、目标与边界

T22.5 已回答每个 GT6 source row 是否属于 `ordinary_optional`，但没有回答剩余 family 的
每个输入/输出能否由当前 CrucibleCraft runtime 表达并进入非循环的玩家路径。T38–T41
只对各自候选 lock 在 R0 做 operand disposition，因此缺 prefix、molten、独立方块/MTE
或 acquisition 时，问题会在内容卡中途才暴露。

本卡的目标是用 pinned revision 的已有投影和当前 runtime state，对 T41 closing 后的全部
5,305 个 family 做 family-atomic partition。产物必须让下一张内容卡只从已闭合的切片签发，
而不是按一个 host 整包假定可做。

本卡采用以下政策：

1. **正式划分，而不是仅写参考报告。** `already_expressed` 和有充分语义证据的
   `later:recycling` / `later:object_expression` / `later:combinatorial/<host>` 会进入
   append-only disposition lock，并从当前 execution gap 扣除；这不是 recipe completion。
2. **不因规模而延期。** Bath、Mixer、Smelter 的 relation 数或模板大小不能单独成为
   reclassify 理由。每个 family 必须有明确 operand/object/representation 证据、future owner
   和 recheck condition。
3. **材料 form 与独立对象分开。** 已知 CC material 上缺 form 或 molten 的 family 留在
   `needs_prefix_or_molten`，等待材料/有界 form 工作；不得把它们伪装成独立对象延期。
4. **下一内容卡优先方向为 Drying ready slice。** 这只是 T43 的优先签发意图，不是
   topology assignment。T43 R0 必须从 T42 closing overlay 重新冻结实际 family IDs 和规模；
   不默认接收 Drying 的全部 152 families。

`1,819` 个 Smelter MTE 回收、Bath 1,116-row family 等是本卡要复算和证据化的诊断对象，
不是本计划的预冻结分母。除 5,305 opening 外，所有 bucket count 都只能由 R2 的构建结果
得出。

## 2. 账本语义与拓扑修订

T35 的 5,718-family / 78,682-row foundation 及 T37–T41 closing artifacts 始终只读。本卡
不会把历史 `ordinary_optional` row classification 改写为新的来源分类。

为避免“既留在 gap，又宣称它不阻挡 storage”的双重记账，T42 closing 采用三本互不替代的账：

```text
ordinary family universe
  = 5,718 historical source-backed families；T35 永久只读

current recipe execution gap
  = T41 opening 5,305
    - complete-by-prior-runtime-expression
    - phase-reclassified-with-lock

deferred ordinary ledger
  = 每个从 execution gap 移出的 family
    + future_owner + reason + recheck_condition
    + source/operand evidence root
```

- `complete-by-prior-runtime-expression` 是 `already_expressed`，必须证明整族所有 relation
  均已在 live runtime 表达；它单列 `already_expressed_delta`，不得写成 T42 完成配方。
- `phase-reclassified-with-lock` 是经人工确认的 semantic deferral，单列
  `reclassification_delta`；它也不得写成 completion。
- `needs_prefix_or_molten`、不满足 reclassify 条件的独立对象，以及任何 `partial` family
  保留在 execution gap。

workflow / roadmap 的 storage 顺序需在 T42 关闭时修订为：

```text
T42 partition
  -> current_closure_ready recipe waves
  -> storage / presentation / multiblock bundles may interleave serially
  -> deferred recycling / object-expression / combinatorial owner tracks
  -> 1.x joint exit gate
  -> nuclear source/physics census
```

这只解除“尚无运行时表达证明的长尾”对 storage、EMI、表现层和多方块卡的前置阻塞；
不允许并行 active 内容卡。1.x exit gate 仍要求 execution gap 为零，且 deferred ordinary
ledger 中每一项都已关闭或经独立、明确的 post-1.x scope decision 处理；不能让
`later:*` 变成无期限删除。

## 4. R1 · Family-to-operand snapshot、runtime inventory 与真实 B0

新增：

```text
tools/t42_family_operand_snapshot.json
tools/t42_runtime_expression_inventory.json
tools/t42_reachability_baseline.json
```

`family_operand_snapshot` 是压缩的 family → normalized relation → operand 索引，不复制整份
GT6 dump。每个 operand 保留原始 `source_map`、recipe index、row hash、side、count/action、
item/fluid id、meta、material/form、alias 和 relation stable key。

- `--full-replay` 从 pinned dump 重建 snapshot，并用 T35 template/family membership 验证；
  Mixer 沿用其既有 template-index membership 规则。
- 日常 `--check` 只读 committed snapshot、`gt6_l1b_selected_recipe_operands.json` 和
  compact receipts，不要求本地 dump。
- source row、family membership 与 snapshot 的 semantic roots 三向相等；未知映射、缺 row 或
  multiple-family membership 均失败。

`runtime_expression_inventory` 必须区分，而非仅检查 namespace：

| 类别 | 当前权威 |
| --- | --- |
| CC material form | material registration gate + material-form authority + material/prefix definitions |
| molten / chemical fluid | material molten declarations、chemical gates、`t22_5_fluid_mapping` |
| CC static item/block/MTE | `t35_runtime_registry`，并由 Java registry fixture 双向验证 |
| vanilla item/block | 显式版本化 allowlist / Java registry fixture；`minecraft:` 前缀本身不是证明 |
| component expression | `ModComponents` 与 compact codec 支持的 component predicates |
| published relation | T21、T37–T41 的 committed logical relation signatures |

`reachability_baseline` 不能直接复用旧 `t21_operand_reachability.json` 当作当前世界。
它应从 T21 baseline 出发，按已关闭卡的 locked support / production 顺序重放：

```text
T21 base (contains T37/T38)
  -> T39 support and production
  -> T40 support and production
  -> T41 support and production
```

每层只在其输入已位于前一层时加入输出，并记录 B0 semantic root。T42 candidate、future
required forms、future acquisition/support 和 T42 自身输出一律不得加入 B0。流体 quantity /
container 仍是 typed-closure 的已知近似；含 fluid 的 ready 判定必须输出
`fluid_reachability_approximate=true`，并在后续 production lock 再验证容器、容量和取得链。

## 5. R2 · 五桶 blocker overlay

新增：

```text
tools/t42_blocker_overlay.schema.json
tools/t42_blocker_overlay.json
tools/t42_operand_disposition.json
tools/t42_wave_candidates.json
```

先为每个 operand 复用现有四态写出 `proven_equivalent`、`needs_current_expression`、
`phase_deferred` 或 `unsupported`，再以 relation 全量结果归约到 family；任一 relation
未通过，family 不得进入 `current_closure_ready`。

每个 family 恰有一个 `primary_bucket`：

| Bucket | 准入 / 含义 | 对当前 execution gap |
| --- | --- | --- |
| `current_closure_ready` | host 当前可运行；所有 operand 有等价 runtime expression；所有输入在 B0；输出已注册；已有 exact 或已验收参数化表示 | 保留，供内容 lock 选择 |
| `needs_prefix_or_molten` | material 已知，但缺 factual/source-backed form、prefix、molten 或 chemical fluid | 保留，交有界 material/form 波 |
| `needs_unique_block_or_mte` | 依赖的对象是独立方块、MTE、状态物、容器、箱体、管道、C-Foam 或 fixed GT object，非 material form | 等待 R3 disposition |
| `combinatorial_unproven` | relation expansion 需要 parameterized/slot/shard/player-path 证明而当前没有 | 等待 R3 disposition |
| `already_expressed` | 所有 relation 均与当前 live relation 完全相同 | 等待 R3 exact accounting |

行中还必须保留次级 blockers，至少包括：

```text
family_id, host, template_key, membership_kind, relation_count,
primary_bucket, secondary_blockers, representation_status,
missing_forms, missing_fluids, missing_runtime_ids, unique_objects,
b0_unreachable_inputs, fluid_reachability_approximate,
lossy_aliases, unsupported_semantics, published_relation_matches,
evidence_root_sha256, source_revision
```

`already_expressed` 不得沿用“同 namespace”或 `Ingredient.toString()` 比较。Python 侧实现的
canonical logical relation identity 必须与 `GTRecipeMapLoader.logicalInputIdentity()`、
`recipeOutputIdentity()` 和 duration/EUt 语义对齐，比较 consume/preserve/action/count、
item components、fluid components、outputs、chance、duration、EUt、special value 与 buffering。
仅部分 relation 重合时标记 `partial`，不允许关闭或扣除整个 family。

`wave_candidates` 仅排序，不具生产权威。它按“可运行 host → B0 closure → 已验收表示 →
T14 routed candidate risk”排序，并输出每个 bucket 的 family / row 数、最大族、必要 support
和 runtime work 类型。它不通过“最小 relation count”或 host 名称自动选择下一张卡。

## 6. R3 · Disposition lock 与 gap partition

新增：

```text
tools/t42_disposition_lock.json
tools/t42_gap_partition.json
tools/t42_census_delta.json
tools/t42_card_topology.json
tools/t42_readiness.json
```

overlay 是诊断；只有人工审核后写入的 `disposition_lock` 才能改变 current execution gap。
该 lock append-only，普通 `--write` 不得改写已批准的 reason、owner 或 family selection。

允许的 closing disposition：

| Overlay 结果 | Lock disposition | owner / recheck |
| --- | --- | --- |
| `current_closure_ready` | `retained_current_execution_gap` | 下一 production lock |
| `needs_prefix_or_molten` | `retained_current_execution_gap` | bounded material/form owner |
| `already_expressed` | `closed_by_existing_expression` | `expressed_by` + relation identity root |
| `needs_unique_block_or_mte` 且证实为回收/拆解对象 | `phase_deferred` | `later:recycling` + source object identity + object registration/reachability recheck |
| 其他独立对象且其表达边界已定义 | `phase_deferred` | `later:object_expression/<kind>` + required registry/behavior proof |
| `combinatorial_unproven` 且缺失表示能力已证实 | `phase_deferred` | `later:combinatorial/<host>` + template/slot/shard/B0/load recheck |

以下情况一律不准 reclassify：

- 仅因 Bath、Mixer、Smelter 大，或关系数超过某个阈值；
- material 已知但只有 form/molten 尚未表达；
- 只是 B0 暂时不可达，却能由有界 source-backed support 闭合；
- 只有部分 relation 需要独立对象；
- lossy alias、未知 runtime id 或 output 未注册尚未建立 source object 归属。

`gap_partition` 必须显式公布：

```text
opening_execution_gap = 5305
completion_delta = 0
already_expressed_delta
reclassification_delta
closing_execution_gap
deferred_ordinary_ledger_count
retained_ready_count
retained_needs_form_or_molten_count
partial_family_count = 0
```

`t42_census_delta` 记录的是 current execution disposition 变化，而非“由 T42 实现的 recipe
内容”。每个 reclassified family 必须出现在 deferred ledger，且其 owner/recheck/evidence
不可为空。历史 T35–T41 文件保持不变。

## 7. R4 · T43 交接：Drying ready slice

T42 关闭后，下一次内容卡签发优先检查 `cruciblecraft:drying` 的
`current_closure_ready` slice。选择理由是其 host 已运行、family 体量天然有界，并能验证
“只吃 ready 切片”的新治理模式；这不是把 T43 的 host 或数量写入 T42 topology。

T43 R0 必须重新：

1. 读取 T42 closing `gap_partition` 与 blocker overlay；
2. 从该时刻的 Drying ready family-atomic set 冻结 catalog、candidate 和 production lock；
3. 选择 exact / parameterized representation、publication group 与 query-addressable shard；
4. 复核 B0/B1/B2、player-path support、material forms、输出消费/终端用途及 T14 load；
5. 仅在所需 form 数量小、source-backed、有明确 acquisition 的前提下附带有限 form support。

T43 明确禁止以“补配方”为理由建立一次性 GT 方块/MTE 全目录，或把需要
`later:recycling` / `later:object_expression` / `later:combinatorial` 的 family 混进 lock。
若 Drying ready slice 在 T43 R0 不再满足上述门，则撤回该候选意图并按
`t42_wave_candidates` 重新签发，不以另一个 family 静默补足计数。

## 9. 退出门与非目标

`T42_PARTITION_READY` 的最小条件：

- `owns_families=0`、`publication_delta=0`、`completion_delta=0`；
- opening 5,305 family 与所有 prior lock / census disposition 可复算；
- remaining catalog、operand snapshot、runtime inventory、cumulative B0、blocker overlay、
  disposition lock 和 gap partition 具有一致 semantic roots；
- 每个 family 恰有一个 primary bucket；任何 `partial`、unknown、unmapped 或无证据
  `future_owner` 都 fail closed；
- `already_expressed` 与 reclassification 分列，所有 deferred family 进入 append-only ledger；
- T14 hard ceiling 未修改，且本卡无 load delta；
- `next_issue_id=T43`、`preassigned_host=false`、`preassigned_family_ids=false`，
  `unique_active_content_card=null`；
- `failed_gates=[]`。

明确不做：

- 不重新抓取或修改 GT6 dump，不修改 T22.5 行级来源分类；
- 不制作任何配方、support、木头/方块/MTE catalog、material form、fluid 或 gate overlay；
- 不把 `needs_prefix_or_molten` 当作 recycling，也不为减小 gap 以规模为由延期；
- 不提高 T14 hard ceiling，或在未有准确 runtime 证明前讨论 load 顶；
- 不签发 T43 family/host，不开始 storage、表现层、多方块或核能实现；
- 不把 deferred ledger 当作 1.x exit gate 已满足的证明。
