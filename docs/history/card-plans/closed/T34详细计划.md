# T34 开局对象表现层 · 已撤回关闭计划

> 本计划对应的闭卡已经撤回：它只规划了 three-member 自制表现层，未按 GT6 原始资源核对
> 完整开局分母或 T18 青铜能源链。当前 T34 的范围与关闭判据以 `docs/current/roadmap.md`
> 的重开条目和新的 GT6 runtime-to-art manifest 为准。

## 已锁定的范围

- Firebox 使用 `ART_AUTHORED`：项目原创的 unlit/lit 模型与纹理。
- Anvil 与 Crucible 使用 `ART_DERIVED`：设备专属灰度 mask 加既有 material tint，
  所有可着色面维持 `tintindex: 0`。
- first-hour scope 不是全局 recipe closure 的时间线替代；它由 T33 receipt 中可达的原版
  种子和五条明确的手工路线限定为 anvil（S1）、crucible（S2）、firebox（S2）。

## 实施与审计

1. 建立 `tools/t34_presentation_policy.json` 和
   `tools/build_t34_presentation.py`，固定路线、成员、表现分类、占位纹理禁令与载荷。
2. 将 anvil/crucible 改为独立 `starting_device/*_mask.png`，拒绝继续绑定
   `metal_surface`。
3. 让 `ModBlockStateProvider` 将 `FireboxBlock.LIT` 投影到
   `firebox_unlit` / `firebox_lit`；item 使用 unlit model，中文 block 名同步生成。
4. 更新 T18 的 converter resource contract，使其记录 firebox 的两个 authored state
   model，而不是已删除的 generated cube；重推导受影响 T18/T19 receipts。
5. 在 `presentation` integration profile 注册 builder、Python 测试和路径归属。

## 关闭判据

- `tools/t34_presentation.json` 为 `T34_PRESENTATION_READY`；
- 三个成员均有 `ART_DERIVED` 或 `ART_AUTHORED`，没有 `ART_PLACEHOLDER` /
  `ART_MISSING` 或未声明的 `metal_surface` / `firebrick` 绑定；
- `python tools/verify.py integration --profile presentation`、T34 scoped `dev` 和
  `gradlew.bat test --no-daemon` 均成功；
- 默认 datagen 两次成功运行，排除 `.cache` 的 generated tree 无漂移；
- `T32-VD-001` 继续记录为 open，recipes integration 不作为本卡门禁。
