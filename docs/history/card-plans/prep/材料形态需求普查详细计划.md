## 0. 开场判断

身份卡 `registry/hybrid-material-identity` 已关。unique-active 空窗。
现行痛点不是「材料表没灌完」，而是配方 / 获得格卡把**已经能对上 GT6 的缺形态**
和激光气体、染料流体、未映射 OD 混进同一个 blocked 堆。

本 prep 只做发现。门仍是 GT6 `OP.*` / `ItemGenerator` / dump 已用格；
对不上的继续 blocked，禁止发明。

## 1. 分母

权威输出：`tools/waves/prep/material-form-demand-census/census.json`。

| 集合 | 用法 |
| --- | --- |
| `openable` | 真的还没进 `gate.materials` 的已知需求。后继 form-open unique-active 只消化这份 |

### 需求源改造（实施）

前置：[GT6 翻译链映射修复](GT6翻译链映射修复详细计划.md) 先关，否则需求里混着漏映射。

1. `build_semantic_coverage.py --write` 另写 `form_demand_pairs.json`（同目录，提交进仓库，
   让 CI 上的 `census.py --check` 不需要 dump）：每条 `missing_material_form` 记
   `cc_material`、`cc_form`、`gt_prefix`、受影响行数、各图行数。
2. `census.py` 新增 `collect_dump_demand()` 读这份文件，作为主需求源；`collect_gap_demand()` 与
   `collect_catalog_demand()` 保留为补充源，每对的 `sources` 记全部来源。
3. `classify_pair()` 不变。新增 `deferred_by_decision`：`crate.*`、`bulletGt*`、`storage.raw/gem/plateGem`。
4. `counts` 新增 `dump_demand_pairs`、`dump_demand_rows`；`openable_by_form` 附受影响行数，给开门卡排序。
5. `tools/tests/test_material_form_demand_census.py` 补：dump 源存在时 `openable` ⊇ 旧源的 `openable`；
   `deferred_by_decision` 不进 `openable`。

### 1.2 实施结果（2026-09-25）

- `form_demand_pairs.json` 已由逐行分类生成：13,915 个 `(材料, 形态)` 对，
  覆盖 146,815 个源行，并记录 GT 前缀与各 GT6 图行数。
- `census.py` 已将 dump demand 作为主源，旧 `current_gap` / blocker catalog 作为补充源；
  当前普查为 13,982 个合并需求对、12,854 个 `openable`、59 个
  `gated_unresolved`，未修改 `material_registration_gate.json`。
- `census.py --check` 与材料形态测试通过；`openable_rows_by_form` 可供后继开门卡排序。
