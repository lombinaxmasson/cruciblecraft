## 2026-09-02 · 关卡后补记：线上写法 ≠ Holder 粒度

实施时核对 GTM：物品侧已经一边（独立 registry id，栈上通常无材料
NBT）。配方也进原版 RecipeManager，`matches()` 永远 false，再填自己的
库——和 dedicated 从 manager 重建同一合同。

差的是 Holder 里装什么。GTM 一条小机器配方 + 优先 tag；我们仍是
1 family = 1 RecipeHolder = exact relations。本卡只换线上写法
（整表 NBT → family 内字典二进制）。单条不再撞 `NbtAccounter`；
5651 个 family 加 eager 仍约 4.09 MiB，下一扇门是 Varint21，靠
splitter，不是再拆 Holder。

没有改成「一条小配方 + tag 输入」。电路 component 也不是这次。
若以后要更像 GTM：另开 parameterized / tag（语义变了），或 §3.2
只切传输且仍带同一个 `family_id`。本卡测过单条 < 512 KiB，没走
§3.2。READY 只证明独立客户端进得去、family 合同没改。
