## 0. 这一阶段是什么

| 阶段 | 产物 | 主导风险 |
|---|---|---|
| 一 | 材料事实 | 事实缺失或伪造 |
| 二 | 通用架构 | 架构做错，晚了重写一层 |
| 三 | **可玩的工业阶梯** | 判据不可证伪 |
| **四** | **有纵深、可发布的版本** | **量、真实规模性能、填充中混入新系统** |

第四阶段第一次以「量」为主导。三条新风险：

1. **真实规模性能未经验证。** 至今全部性能结论来自静态分析、单元基准与合成分布（T14 的 1× / 5× / 20× 用的是 compact distribution，不是真实基地）。没有任何一次是在实际存档上跑出来的。
2. **填充批次会混入新系统。** 投影一个 RecipeMap family 时，某些行会要求当前不存在的机器行为。若就地实现，批次判据会被稀释。
3. **收尾债随内容线性增长。** lang zh_cn 366 / 3,167 = 11.6%，每一卡都在拉大分母。

## T20 · 化学链纵深（首个不可压族批次） ⚪

**判据**

> 按 T13 分母与 T14 family projection schema，投影石油—化工主链使其在生存中可从原油/天然气走到至少三种下游产物并回到工业链；同批次同时作为**不可压族的载荷压测**：逐行标记 `prefix_matrix` / `composition_matrix` / `named_reaction`，三类分别记账，`named_reaction` 的真实压缩比必须实测而非假设。

**依赖**：T13、T14、T18

**为什么第一张**

两个理由叠加：

1. **最大的体验断裂。** T11 建了抽取器、气体云、两种发电机，产物是原油与天然气，下游 2 条配方。
2. **最坏情况要趁早压测。** `named_reaction` 结构上不可压（1 logical = 1 authored fact），是 T14 hybrid 从未被测过的输入形态。当前 eager soft 18,000 已用约 16,650，lazy hard 56,000 只用 2,225——**headroom 在 lazy 轴，而不可压族正好该走 lazy 轴**。若先填可压缩内容，eager 轴填满后才发现问题，顺序就反了（9.1 的同一逻辑）。

**开工门禁**

1. **三类形状标记先于投影**：T13 的 in-scope 行按 `prefix_matrix` / `composition_matrix` / `named_reaction` 分类，`unclassified = 0`。这是 T13 补的一列，若未做，本卡不开工。
2. **`composition_matrix` 优先于 `named_reaction`**：655 个材料有非空 `composition`，其中 205 个 `no_decompose = false`。GT6 从 `mComponents` 程序化生成电解/离心分解配方——CC 已导入该控制开关但未导入生成器。这根轴是零，先开它，再谈逐条投影。
3. **压缩指标先改**：新增 `logical rows ÷ authored facts`，与 datapack 文件数分列。extruder 当前是 1 : 1（文件打包而非语义压缩），`crusher/ingot_to_dust` 是 1773 : 1。两个数并列才看得出哪些族真被泛化。
4. **eager/lazy 选取依据先落定**：`shadowOrder % 5` 是未测量常数（实测钢/锡/镍的挤压行 100% 落在 lazy 侧）。本卡新增族不得沿用该常数，需按频度/tier 选取或在数据中声明为 `UNMEASURED`。

**先算的数字**

- 石油—化工主链 in-scope 行数，按三类形状分列。
- `composition_matrix` 轴可覆盖的分解/合成行数（205 可分解材料 × 电解 + 离心 + 逆向合成）。
- `named_reaction` 投影后的 lazy 增量与 lazy hard ceiling 56,000 的余量。
- 各族的 `logical ÷ authored facts`，与 extruder 的 1:1、矿石族的 1773:1 并列。

**子判据**

- **T20a · 形状分类**：三类标记 `unclassified = 0`。
- **T20b · 组成轴开通**：分解/合成由 `composition` 展开，非逐条手写。
- **T20c · 主链贯通**：生存中原油/天然气 → ≥3 种下游产物 → 回到工业链，端到端 GameTest。
- **T20d · 载荷实测**：三类形状各自的压缩比与 lazy 增量落账，hybrid 在不可压输入下的实测数据齐全。

**范围之外**

- 不投影与石油—化工主链无关的 map。
- 不为塞进预算降低等价判据。
- 不实现主链所需之外的新机器行为——遇到即按 2.1 停下登记。

**完成信号**

1. 石油链不再在第一步断裂。
2. `composition_matrix` 轴从 0 变为可用，且其压缩比实测。
3. hybrid 架构在不可压输入下的实测结论写入 9.5。
4. 压缩指标改为对文件打包不敏感。

## T21 · 真实规模性能基线 ⚪

**判据**

> 在真实存档上建立一次可复现的规模基线：机器数、管道长度、cover 数、活跃配方数达到预声明的规模点，测 tick 时间分布、BE 同步包速率、内存与区块加载；把至今全部**静态推断出的性能结论**逐条对照实测，确认或推翻。

**依赖**：T14（载荷门禁）；可与 T20 并行

**为什么单列一卡**

至今所有性能结论均来自静态分析与合成基准：`PipeTopology` 的组件遍历、流体管的 `sendBlockUpdated` 频率、发电机每 tick 同步、`chemicalFluids` 与 `acceptsInput` 的线性扫描、`CapacityMatcher` 的稠密图、`resolveDeposit` 的列扫描。**没有一条被真实基地验证或推翻过。**

T14 的 1× / 5× / 20× 用的是 compact distribution，不是真实访问分布——这也正是 `shadowOrder % 5` 的划分能通过基准却把钢全放进 lazy 侧的原因：**基准的分布假设与真实游玩不同。**

**开工门禁**

1. 规模点先声明：机器数 / 管道格数 / cover 数 / 活跃配方数 / 玩家数，三个规模点。
2. 测量项先声明：server tick p50/p95/max、BE 同步包/秒、堆占用、区块加载耗时、客户端帧时间。
3. 建基地的方式必须可复现（结构文件或脚本），不接受手搭。
4. 历史静态结论逐条列出，每条标注「预期表现」，测完对照——**避免只看总数不看具体假设**。

**先算的数字**

- 三个规模点各自的预期 tick 预算与实测。
- 每条历史静态结论的预期 vs 实测，确认 / 推翻 / 无法观测三分。
- 与 T14 的合成基准的差异倍率。

**子判据**

- **T21a · 可复现基地**：三个规模点的存档/脚本进 CI 或工具链。
- **T21b · 基线测量**：五类指标齐全。
- **T21c · 历史结论对照**：逐条确认或推翻，无「无法观测」残留（有则登记悬案）。

**范围之外**

- 不在本卡做优化——只测量。发现的问题登记，按证据排期。
- 不重写任何已通过测量的组件（沿用 T12e「无测量证明不提前重写」）。

**完成信号**

1. 第一次有真实规模的性能基线，后续每卡可对照。
2. 历史静态结论从推断变为观测。
3. 优化排期由实测驱动而非由代码阅读驱动。

## 2. 第四阶段方法论增补

### 2.1　填充批次遇到新系统需求必须停下登记，不得就地实现

**依据**

第四阶段首次以量为主导。投影 RecipeMap family 时，某些行会要求当前不存在的机器行为、能量类型或结构语义。若就地实现，批次的判据被稀释成「投影 + 一堆临时实现」，收尾时无法判断哪部分被验证过。

**规则**

> 填充批次中出现需要新行为、新能量身份、新结构语义的行时：该行标记 `blocked_by_new_subsystem`，登记悬案并给出独立卡片编号，**本批次跳过该行继续**。批次可以带着已登记的 blocked 行关闭；不得在批次内实现。

### 2.2　性能结论必须区分「静态推断」与「实测观测」

**依据**

至今全部性能结论来自读代码与合成基准。`shadowOrder % 5` 的 eager 划分能通过 20× 基准，同时把钢/锡/镍的全部挤压行放进 lazy 侧——**基准的分布假设与真实访问分布不同，基准结构上抓不到这件事。**

**规则**

> 任何性能相关的判据或悬案，必须标注证据种类：`STATIC_INFERENCE` / `SYNTHETIC_BENCHMARK` / `MEASURED_AT_SCALE`。
> 只有 `MEASURED_AT_SCALE` 可以作为「不需要优化」的关闭理由。
> 合成基准必须声明其分布假设，并说明该假设与真实使用的差异。

### 2.3　分母不是待办数

**依据**

452 canonical prefix、96 canonical kind、95 canonical map 是**可比较分母**，不是实现清单。第三阶段第 0 节已把「类文件数当实现分母」列为伪完成度；分母直接当待办是同一错误的镜像。

**规则**

> 任何以 canonical 分母为输入的卡片，第一步必须是范围分类，第二步才是实现。判据写「in_scope 全部落地」，不写「N / M 全部实现」。

## 4. T24 之后

**第五阶段（T25 起）候选**：G10 五条轴、末期内容与新物理、GT6U 按类拆分、多方块 C/D、O-29 若未插入。

**终局定义（建议在 T20 开工时写死一句话）**

现在项目有三个可能的「完成」，它们的差别很大：

1. **工业主链完整**：95 map 中的工业子集、96 kind 中的 processing 子集、30 multiblock 的 A/B/C/D 全部——第四、五阶段可达。

3. **GT6 + GT6U**：再加 GT6U 的 mixed 部分。

**建议在 T20 开工门禁里选定一个并写进总体规划。**理由与第二阶段末尾相同：这句话现在写是免费的，T24 关闭时再写，代价是一次没有指引的阶段边界。
